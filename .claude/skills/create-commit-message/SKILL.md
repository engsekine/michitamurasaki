現在の変更差分を分析し、コミットメッセージ規約に基づいた候補を 3 つ提案し、選択されたメッセージでコミットまで実行します（旧 `/suggest-commit` の提案機能を統合）。

## 使い方

```
/create-commit-message
```

## 手順

### 1. 変更内容の収集

以下のコマンドを順に実行する:

```bash
git diff --cached --stat        # ステージング済みの変更ファイル一覧
git diff --cached               # ステージング済みの差分詳細
```

**ステージング済みの差分がある場合はそちらのみをコミット対象とし、未ステージの差分は無視する。**

ステージング済みの差分がない場合のみ、以下を実行:

```bash
git status --short              # 未ステージ・未追跡の変更一覧
git diff --stat                 # 未ステージの変更ファイル一覧
git diff                        # 未ステージの差分詳細
```

どちらもない場合は「変更がありません」と出力して終了。

スタイル参考として直近のコミットも取得:

```bash
git log --oneline -5            # 直近のコミットメッセージ（スタイル参考）
```

### 2. コミットメッセージ規約の参照

CLAUDE.md のコミットメッセージ規約に従い、プレフィックスを判定する:

| プレフィックス | 用途 |
|--------------|------|
| `feat:` | 新機能 |
| `fix:` | バグ修正 |
| `docs:` | ドキュメントのみ |
| `refactor:` | リファクタリング（機能変更なし） |
| `test:` | テストの追加・修正 |
| `chore:` | ビルド設定・依存パッケージ更新 |

### 3. コミット名候補の作成

変更内容を分析し、以下のルールで候補を 3 つ作成する:

**ルール:**
- プレフィックス + 半角スペース + 変更内容の要約
- 要約は日本語で簡潔に（プレフィックスを含めて50文字以内を目安）
- 「何を」「なぜ」が伝わる内容にする

**スコープ:**
- 変更が `specs/<NNN>-<feature>` に対応する機能の実装なら、スコープ付きプレフィックスにする（例: `feat(026): 購入ページへの常設導線を追加`）
- 直近のコミット履歴（手順1で取得）にスコープ付きが多い場合はそのスタイルに合わせる
- 対応する feature がない変更（横断的な修正等）はスコープなしでよい

**複数プレフィックスが該当する場合の優先順位:**
1. `fix:` — バグ修正が含まれていれば最優先
2. `feat:` — 新機能が含まれていれば次に優先
3. その他 — 変更の主目的に合わせる

**3候補の出し方:**
- 候補1: 最適と判断したプレフィックス + 最も簡潔な要約
- 候補2: 同じプレフィックスで別の切り口の要約（例: 「何を」重視 vs 「なぜ」重視）
- 候補3: 別のプレフィックスが妥当な場合はそちらで提案。妥当でなければ候補1と同じプレフィックスでより詳細な要約

### 4. 候補の選択

AskUserQuestion ツールで 3 候補を提示し、ユーザーに選択してもらう:

- 質問: 「どのコミットメッセージでコミットしますか？」
- 選択肢: 候補 1〜3（最適と判断したものを先頭に「（推奨）」を付ける）
- 各選択肢の description に、そのプレフィックス・要約を選んだ理由を一言添える
- ユーザーは「Other」で自由入力もできる（その場合は入力されたメッセージをそのまま使う）

### 5. コミットの実行

**ステージング済みの差分をコミットする場合**（手順1でステージ済みがあった場合）:

```bash
git commit -m "<選択されたコミット名>"
```

**未ステージの差分しかない場合**: コミット対象のファイル一覧を提示し、ステージしてよいか確認を取ってから実行する:

```bash
git add <対象ファイル...>       # git add -A は使わず、手順1で確認したファイルを明示的に指定する
git commit -m "<選択されたコミット名>"
```

- 意図しない未追跡ファイル（一時ファイル等）を巻き込まないため、`git add -A` / `git add .` は使わない
- コミット後に `git log --oneline -1` で結果を表示して完了

### 6. 出力

```
コミットしました
═══════════════════════════
<git log --oneline -1 の出力>
対象: <ファイル数>ファイル
```
