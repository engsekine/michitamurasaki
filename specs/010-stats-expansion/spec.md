# Feature Specification: 統計の拡充（年別・月別本数推移 / 水温×季節 / 最大深度推移）

**Feature Branch**: `010-stats-expansion`

**Created**: 2026-06-13

**Status**: Draft

**Input**: User description: "統計の拡充 — 年別・月別の本数推移、水温×季節、最大深度の推移グラフ。get_dive_stats RPC の拡張で対応できます"

## 概要

既存のダッシュボード累計統計（[`specs/003-dashboard/`](../003-dashboard/spec.md)）を拡充し、ダイバーが自分の活動の「推移」と「傾向」を視覚的に振り返れるようにする。本 feature には以下 3 つの要素を含む。

1. **年別・月別の本数推移**: ダイビング活動のペースを時系列で把握する
2. **水温×季節の傾向**: 月ごとの水温傾向から季節ごとの装備・スーツ選びの参考情報を得る
3. **最大深度の推移**: ダイバーとしての経験・スキルの深まりを時系列で実感する

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 年別・月別の本数推移を確認する (Priority: P1)

ダイバーとして、自分のダイビング本数が年ごと・月ごとにどう推移しているかをグラフで確認でき、「今年は去年よりたくさん潜れているか」「どの月によく潜っているか」を一目で把握できる。

**Why this priority**: 本 feature の中核価値。累計値（既存統計）では分からない「活動のペース」を可視化することで、ダイバーが自分の歩みを実感し継続のモチベーションにつなげられる。このストーリー単体で統計拡充として成立する MVP になる。

**Independent Test**: 複数年・複数月にまたがるダイブログを登録したユーザーでログインし、統計表示を開いて年別の本数と月別の本数推移がグラフで表示されることを確認できる。水温・深度の表示とは独立にテスト可能。

**Acceptance Scenarios**:

1. **Given** 複数年にまたがるダイブログを持つ認証済みユーザー, **When** 統計表示を開く, **Then** 年ごとのダイビング本数が時系列のグラフで表示される
2. **Given** 複数月にダイブログを持つ認証済みユーザー, **When** 統計表示を開く, **Then** 月ごとのダイビング本数の推移がグラフで表示される
3. **Given** ログが 1 件もない月が期間内にあるユーザー, **When** 月別推移を見る, **Then** その月は 0 本として表示され、欠落（歯抜け）にならない
4. **Given** ダイブログが 0 件の認証済みユーザー, **When** 統計表示を開く, **Then** グラフの代わりに「ログを記録すると統計が表示される」旨の空状態が表示される
5. **Given** 未認証のユーザー, **When** 統計表示の URL を開く, **Then** ログイン画面にリダイレクトされる

---

### User Story 2 - 最大深度の推移を確認する (Priority: P2)

> **廃止（feat/design-change・2026-07-10）**: 最大深度・平均水温（US2 / US3）のチャートは TOP から削除した。統計の推移は **年別ダイビング本数 / 月別ダイビング本数（直近 12 ヶ月）** の 2 枚構成とする。関連 FR-004〜FR-006 は失効し、RPC も月別本数のみの集計に変更（data-model.md 参照）。

ダイバーとして、自分が記録してきた最大深度が時間とともにどう変化しているかをグラフで確認でき、経験の深まり（より深く潜れるようになった、安定した深度で潜っている等）を振り返られる。

**Why this priority**: 「ダイバーとしての成長を実感する」というプロダクト価値に直結するが、活動ペースの把握（US1）より利用頻度は低い。US1 と独立して提供可能。

**Independent Test**: 深度の異なるダイブログを複数登録したユーザーで統計表示を開き、最大深度の推移グラフが表示されることを確認できる。本数推移・水温の表示とは独立にテスト可能。

**Acceptance Scenarios**:

1. **Given** 深度を記録したダイブログを複数持つユーザー, **When** 統計表示を開く, **Then** 最大深度の推移が時系列のグラフで表示される
2. **Given** 同じ期間（同月）に複数本のログがあるユーザー, **When** 深度推移を見る, **Then** その期間の代表値としてその期間内の最大深度が表示される
3. **Given** ダイブログが 0 件のユーザー, **When** 統計表示を開く, **Then** 深度推移グラフの代わりに空状態が表示される

---

### User Story 3 - 水温と季節の傾向を確認する (Priority: P3)

ダイバーとして、月ごとの水温の傾向（平均水温など）をグラフで確認でき、「この季節はどのくらいの水温か」「ウェットスーツ / ドライスーツの切り替え時期はいつ頃か」の判断材料にできる。

**Why this priority**: 装備計画に役立つ実用情報だが、水温は任意入力項目のため記録がないユーザーには価値が薄い。US1 / US2 と独立して提供可能。

**Independent Test**: 水温を記録したダイブログを複数月分登録したユーザーで統計表示を開き、月別の水温傾向がグラフで表示されることを確認できる。本数・深度の表示とは独立にテスト可能。

**Acceptance Scenarios**:

1. **Given** 水温を記録したダイブログを複数月分持つユーザー, **When** 統計表示を開く, **Then** 月ごとの水温傾向（平均水温）がグラフで表示される
2. **Given** 同じ月に水温の異なる複数本のログがあるユーザー, **When** 水温傾向を見る, **Then** その月の平均水温が表示される
3. **Given** 水温が未入力のログだけを持つユーザー, **When** 統計表示を開く, **Then** 水温グラフの代わりに「水温を記録すると傾向が表示される」旨の空状態が表示される
4. **Given** 水温入力済みと未入力のログが混在するユーザー, **When** 水温傾向を見る, **Then** 未入力のログは集計から除外され、入力済みのログのみで平均が計算される

---

### Edge Cases

- ダイブログが 1 件のみの場合でも、グラフ（または単一点の表示）がエラーにならず表示されること
- ログが 1 年分に満たない場合、存在する期間のみで年別・月別表示が成立すること
- 水温が一部の月だけ記録されている場合、その月だけ水温グラフに表示され、未記録の月は欠測として扱われること（0℃ と誤表示しない）
- 長期間（10 年分など）のログがある場合でも、グラフが読み取れる粒度で表示されること
- 他のユーザーのログが統計に混入しないこと（本人のログのみ集計）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは認証済みユーザーに対し、本人のダイブログを年ごとに集計した本数推移を表示しなければならない
- **FR-002**: システムは認証済みユーザーに対し、本人のダイブログを月ごとに集計した本数推移を表示しなければならない
- **FR-003**: システムは集計期間内にログのない月・年を 0 本として扱い、推移表示を歯抜けにしてはならない（ダイブログを 1 件以上持つユーザーは、月別の対象期間の全月が 0 本でも 0 本の推移として表示する）
- ~~**FR-004**: システムは本人のダイブログの最大深度を期間（月）ごとの代表値（期間内最大値）として時系列で表示しなければならない~~（feat/design-change で廃止）
- ~~**FR-005**: システムは水温が記録されたログのみを対象に、月ごとの平均水温を表示しなければならない~~（feat/design-change で廃止）
- ~~**FR-006**: システムは水温未入力のログを水温集計から除外し、未入力を 0℃ として扱ってはならない~~（feat/design-change で廃止）
- **FR-007**: システムはダイブログが 0 件の場合、推移グラフ群の代わりに記録を促す空状態を表示しなければならない（水温グラフ固有の部分空状態は feat/design-change で廃止）
- **FR-008**: システムは統計の集計対象をログイン中のユーザー本人のログのみに限定しなければならない
- **FR-009**: 各グラフには、グラフを視認できないユーザーにも内容が伝わる代替手段（テキストによる説明・データの代替表現）を提供しなければならない

### Key Entities

- **ダイブログ（既存）**: 統計の元データ。潜水日・最大深度・水温（任意入力）を持つ。本 feature による新規属性の追加はない
- **年別本数集計**: 年をキーとした本数の集計値。ダイブログから導出される（保存はしない）
- **月別本数集計**: 年月をキーとした本数の集計値。ダイブログから導出される（保存はしない）
- **月別水温集計**: 年月をキーとした平均水温。水温が記録されたログのみから導出される（保存はしない）
- **月別最大深度集計**: 年月をキーとした期間内最大深度。ダイブログから導出される（保存はしない）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ダイバーは統計表示を開いてから追加の操作なしで、年別・月別の本数推移を確認できる
- **SC-002**: 統計表示は通常のデータ量（数百本のログ）で 2 秒以内に表示される
- **SC-003**: 水温未入力のログが混在していても、水温傾向が誤った値（0℃ 扱い等)で表示されることがない
- **SC-004**: ログ 0 件のユーザーが統計表示を開いてもエラーにならず、次の行動（ログ記録）への導線が表示される
- **SC-005**: 複数年のログを持つユーザーが「去年と今年の本数の違い」を 10 秒以内に読み取れる

## Assumptions

- 統計の表示場所は既存のダッシュボード（TOP）の統計エリアを拡張する形とする（新規の専用ページは設けない）。詳細な画面構成は計画フェーズで決定する
- 月別推移のデフォルト表示期間は直近 12 ヶ月とする。年別推移は記録のある全期間を対象とする
- 最大深度・水温の推移も月別本数と同じ「直近 12 ヶ月」を対象とする（全期間の深度・水温推移は本 feature のスコープ外）
- 水温の「季節」傾向は月単位の集計（1〜12 月）で表現する。暦上の四季（春夏秋冬）への分類は行わない
- 集計はダイブログの潜水日（記録された日付）を基準とする。タイムゾーンの違いによる日付ずれは考慮しない（日付のみ保持のため）
- 統計の元データは既存のダイブログのみで、本 feature による新しいデータ入力項目の追加はない
- 既存の累計統計（累計本数 / 潜水時間 / 最大水深 / 訪問スポット数）の表示は維持する
