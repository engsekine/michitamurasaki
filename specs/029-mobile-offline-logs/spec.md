## User Scenarios & Testing *(mandatory)*

ダイビングの現場（ボート上・離島・海辺）は**圏外が日常**である。既存の Web 版は記録・閲覧ともにオンライン前提のため、「潜った直後の記憶が新しいうちに書く」という本サービスの核となる行動が現場でできない。第 1 段階のモバイルアプリは、この「現場で書けない」問題の解消を中心に、閲覧・持ち出し（ダウンロード / エクスポート）までを提供する。

### User Story 1 - オフラインでのログ作成とオンライン転送 (Priority: P1)

ダイバーは、圏外のボート上や離島でもモバイルアプリでダイビングログ（日付・場所・深度・時間などの記録）を作成できる。作成したログは端末に安全に保存され、通信が回復すると自動的にサーバーへ転送されて、Web 版と同じログ一覧に反映される。

**Why this priority**: 「潜った直後に書く」は紙のログブックが担ってきた本質的な行動で、これをデジタルで代替できることがモバイルアプリを作る最大の理由。この 1 ストーリーだけでも「現場で記録 → 帰宅したら Web に揃っている」という完結した価値を提供できる。

**Independent Test**: 端末を機内モードにしてログを作成 → 「転送待ち」として保存されることを確認 → 機内モードを解除 → 自動でサーバーへ転送され、Web 版のログ一覧に同じ内容が表示されることで単独検証できる。

**Acceptance Scenarios**:

1. **Given** 端末が圏外（機内モード）、**When** ログの必須項目を入力して保存する、**Then** ログは端末に保存され「転送待ち」の状態が明示される
2. **Given** 転送待ちのログが 3 件ある、**When** 通信が回復しアプリを開いている、**Then** 3 件すべてが利用者の操作なしでサーバーへ転送され、アプリ上の状態が「転送済み」に変わる
3. **Given** 転送待ちのログがある、**When** Web 版のログ一覧を開く（転送完了後）、**Then** モバイルで作成したログが Web のログ一覧・ダッシュボード集計に反映されている
4. **Given** 転送中に通信が途切れた、**When** 再び通信が回復する、**Then** 同じログが二重登録されることなく、未転送分だけが転送される
5. **Given** 転送がサーバー側の理由で失敗した、**When** 利用者が転送待ち一覧を確認する、**Then** 失敗したログと理由が分かり、手動で再転送を指示できる（ログが消えることはない）
6. **Given** 圏外で作成した転送待ちログがある、**When** アプリを終了・再起動する、**Then** 転送待ちのログは失われず保持されている

### User Story 2 - モバイルでのログ閲覧とダウンロード（オフライン閲覧） (Priority: P2)

ダイバーは、モバイルアプリで自分のログ一覧・詳細を閲覧できる。さらに自分のログを端末にダウンロードしておくことで、圏外でも過去のログ（前回の器材設定・ウェイト量・ポイントのメモ）を参照できる。

**Why this priority**: 現場での「前回どうだったか」の参照は記録と並ぶ紙ログブックの主用途。閲覧が無いとアプリが「入力専用ツール」になり日常利用が定着しない。P1 の転送先確認としても機能するため 2 番目に置く。

**Independent Test**: オンラインで自分のログ一覧・詳細が閲覧できること、ダウンロード操作後に機内モードにしてもダウンロード済みログの一覧・詳細が閲覧できることで単独検証できる。

**Acceptance Scenarios**:

1. **Given** ログイン済みでオンライン、**When** ログ一覧を開く、**Then** Web 版と同じ自分のログが新しい順に表示され、詳細（深度・時間・場所・メモ等）を確認できる
2. **Given** オンラインで「オフライン用に同期」（全件一括ダウンロード）を実行した、**When** 端末を機内モードにしてログ一覧を開く、**Then** 全ログが一覧・詳細とも閲覧できる
3. **Given** 一括ダウンロードを一度も実行していない端末が圏外になった、**When** サーバー由来のログを開こうとする、**Then** エラー画面ではなく「オフラインで閲覧するには同期が必要」なことが分かる案内が表示される
4. **Given** Web 版でログを編集した、**When** モバイルがオンラインで一覧を再表示する、**Then** 編集後の内容が表示される（ダウンロード済みデータも再取得で最新化できる）
5. **Given** 圏外で作成した転送待ちログがある、**When** ログ一覧を開く、**Then** 転送待ちのログもサーバー由来のログと区別できる形で一覧に表示される

---

### User Story 3 - ログのエクスポート (Priority: P3)

ダイバーは、モバイルアプリから自分のログをファイル（印刷に適した形式・データ活用に適した形式）として書き出し、端末への保存や他アプリへの共有（メール送信・クラウド保存など）ができる。

**Why this priority**: ライセンス講習の申請やショップへの提示など「ログの提出」ニーズに応える機能。Web 版に既にあるエクスポート（014）のモバイル版であり、記録・閲覧が成立してからで十分。

**Independent Test**: ログを選んでエクスポートを実行し、生成されたファイルが端末に保存（または共有シートから他アプリへ受け渡し）でき、内容が Web 版のエクスポートと同等であることで単独検証できる。

**Acceptance Scenarios**:

1. **Given** 自分のログが複数ある、**When** 範囲（単一 / 複数選択）を選んでエクスポートを実行する、**Then** 印刷に適した形式のファイルが生成され、端末への保存と他アプリへの共有ができる
2. **Given** データ活用に適した形式を選択した、**When** エクスポートを実行する、**Then** 表計算ソフトで開ける形式のファイルが生成される
3. **Given** 転送待ち（未転送）のログがある、**When** エクスポートを実行する、**Then** 転送待ちのログは対象に含まれないことが事前に分かり、転送を促す案内が表示される（エクスポートはサーバー上のログが対象）
4. **Given** 端末が圏外、**When** エクスポートを実行しようとする、**Then** エラーではなく「エクスポートには通信が必要」な旨の案内が表示される

---

### Edge Cases

- 転送のリトライが重なっても同一ログは 1 件しか登録されない（二重送信・多重リトライへの耐性）
- 圏外でのログ作成中にアプリが強制終了しても、保存済みの下書き・転送待ちデータは失われない
- ログイン有効期限が圏外中に切れた場合、転送待ちのログは保持され、再ログイン後に転送できる（データを失う形でのログアウトはしない）
- 端末の空き容量が不足している場合、ダウンロード・エクスポートは分かりやすいエラーで中断し、既存データを壊さない
- 別端末や Web 版と併用しても、モバイルで作成したログが上書き・消失しない（オフラインで可能なのは新規作成のみで、既存ログの編集はオンライン時に限定して衝突を避ける）
- 日付をまたぐ転送（作成した日と転送した日が異なる）でも、ログの日付は作成時に入力した日付が保たれる
- 転送待ち件数が多い場合（例: 旅行中の 20 本）でも一括で転送され、進捗が分かる
- 機種変更時、転送済みのログはサーバーから復元できる。転送待ちのログの引き継ぎは保証しない（転送を促す案内で予防する）

## Requirements *(mandatory)*

### Functional Requirements

#### ログ作成・転送（US1）

- **FR-001**: 利用者は、通信環境がない状態でもモバイルアプリでログを新規作成・保存できなければならない
- **FR-002**: オフラインで作成したログは端末内に永続化され、アプリの再起動後も保持されなければならない
- **FR-003**: 各ログは「転送待ち / 転送中 / 転送済み / 失敗」の状態を持ち、利用者がいつでも確認できなければならない
- **FR-004**: アプリ起動中（フォアグラウンド）に通信が利用可能なら、転送待ちのログは利用者の追加操作なしに自動でサーバーへ転送されなければならない（アプリを閉じている間のバックグラウンド転送はスコープ外）
- **FR-005**: 転送は冪等でなければならない（リトライ・二重実行でも同一ログが重複登録されない）
- **FR-006**: 転送に失敗したログは端末に保持され、失敗理由の提示と手動再転送ができなければならない
- **FR-007**: 転送されたログは Web 版のログ一覧・集計・検索に他のログと同様に反映されなければならない
- **FR-008**: モバイルのログ入力項目・入力検証は Web 版のログ作成と同等の内容でなければならない（項目の欠落によって Web で不完全なログにならない）
- **FR-009**: オフラインでできるのは新規作成のみとし、既存（転送済み・サーバー由来）ログの編集・削除はオンライン時に限定しなければならない（別端末との衝突回避）

#### 閲覧・ダウンロード（US2）

- **FR-010**: 利用者はモバイルアプリで自分のログ一覧・詳細を閲覧できなければならない（オンライン時）
- **FR-011**: 利用者は 1 回の操作で自分の全ログを端末にダウンロード（一括同期）し、圏外でも一覧・詳細を閲覧できなければならない（個別選択のダウンロードは設けない）
- **FR-012**: ダウンロード済みデータはオンライン時に最新の内容へ更新できなければならない
- **FR-013**: 圏外で端末に無いログ（一括ダウンロード未実行、または前回の一括ダウンロード以降に他端末で作成・編集されたログ）にアクセスした場合は、エラーではなく状況と対処（オンラインで再同期する）が分かる案内を表示しなければならない
- **FR-014**: 転送待ちのログと転送済みのログは、一覧上で状態が区別できなければならない

#### エクスポート（US3）

- **FR-015**: 利用者はオンライン時に、自分のログを印刷に適した形式とデータ活用（表計算）に適した形式でエクスポートできなければならない。圏外時はエラーではなく「エクスポートには通信が必要」なことが分かる案内を表示する
- **FR-016**: エクスポートしたファイルは端末への保存と、端末の共有機能を通じた他アプリへの受け渡しができなければならない
- **FR-017**: エクスポート内容は Web 版のエクスポート（014）と同等の項目を含まなければならない

#### 共通（認証・権限）

- **FR-018**: モバイルアプリは既存のアカウント（メール / Google）でログインでき、Web 版と同じデータにアクセスしなければならない
- **FR-019**: 端末に保存されるログ・認証情報は、その端末の利用者本人のデータに限定されなければならない（他人のデータは端末に保存しない）
- **FR-020**: ログイン有効期限切れ・再ログインが発生しても、端末内の転送待ちログは失われてはならない

### Key Entities *(include if feature involves data)*

- **ローカルログ（転送待ちログ）**: 端末内に保存されるログ。内容は既存のダイビングログと同じ項目 + 転送状態（転送待ち / 転送中 / 転送済み / 失敗）と端末内での作成日時、重複防止のための一意な識別子を持つ
- **ダウンロード済みログ**: サーバー由来のログの端末内コピー（オフライン閲覧用）。読み取り専用で、オンライン時に再取得で最新化される
- **ダイビングログ（既存）**: サーバー上の正のデータ。転送完了後はサーバー側が唯一の正となる
- **エクスポートファイル**: 選択したログから生成される成果物（印刷向け / 表計算向け）。生成後の管理は端末・共有先アプリに委ねる

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 通信環境ゼロ（機内モード）の状態で、ログの作成開始から保存完了まで一度も通信エラーに遭遇せず完了できる
- **SC-002**: 通信回復後、転送待ちのログは利用者の操作なしに 1 分以内に転送が開始され、完了すると Web 版の一覧に表示される
- **SC-003**: 転送のリトライ・再実行を繰り返しても、サーバー上のログ件数は作成した件数と常に一致する（二重登録 0 件）
- **SC-004**: ダウンロード済みのログは、機内モードでも 100% 一覧・詳細が閲覧できる
- **SC-005**: 旅行シナリオ（圏外で 20 本作成 → 帰宅して通信回復）で、全件が自動転送され、進捗と完了が画面で確認できる
- **SC-006**: エクスポートで生成したファイルの記載項目が Web 版エクスポートと一致する
- **SC-007**: アプリ強制終了・再起動・再ログインのいずれを挟んでも、保存済みの転送待ちログの消失が 0 件である

## Assumptions

- 対象プラットフォームは iOS / Android のモバイルアプリ（スマートフォン）。タブレット最適化は本段階のスコープ外
- 第 1 段階のスコープは「自分のログ」に限定する。ソーシャル機能（タイムライン・いいね・フォロー・他人の公開ログ閲覧）、通知、予定・機材管理、写真の添付はスコープ外（オフライン作成ログへの写真添付は将来段階で扱う）
- オフラインで可能な操作は「新規作成」と「ダウンロード済みログの閲覧」のみ。既存ログの編集・削除・公開設定はオンライン時に限定する（同時編集の衝突を構造的に回避するため）
- アカウントの新規登録・パスワードリセットはオンライン時のみ（既存 Web の認証を利用）。アプリ初回利用時はオンラインでのログインが必要
- 「ダウンロード」は明示操作による全件一括のみとする（個別選択なし）。第 1 段階は写真スコープ外でテキストのみのため、全件でも軽量。バックグラウンドでの自動同期は行わない
- エクスポートの生成はオンライン時のみ（既存 Web 版のエクスポートの仕組みを利用し、対象はサーバー上のログ）。オフラインでのファイル生成は将来段階で検討する
- Web 版（service-front）の既存機能・画面は本機能では変更しない（転送されたログが通常のログとして扱われることの確認のみ）
- モバイルアプリのデザインは Web 版とトークン（色・タイポグラフィ等）を共有した同一ブランドとし、操作系はモバイル標準（下部タブ等）に最適化する
