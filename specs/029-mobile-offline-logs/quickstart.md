# Quickstart: モバイルアプリ第 1 段階 手動検証

**Feature**: 029-mobile-offline-logs | **Plan**: [plan.md](./plan.md)

オフライン挙動・冪等性は自動テスト（Vitest の状態機械テスト）に加え、実機/シミュレータでの通し検証を必須とする。

## 前提

```bash
# ローカル Supabase（他セッションと衝突しないタイミングで）
make supabase-reset   # root .env に SMTP_ENABLED=false が必要

# モバイルアプリ起動（iOS シミュレータ / Android エミュレータ / Expo Go 実機）
npm run start --workspace mobile
# 環境変数: mobile/.env（mobile/.env.example を複製）に
#   EXPO_PUBLIC_SUPABASE_URL / EXPO_PUBLIC_SUPABASE_ANON_KEY / EXPO_PUBLIC_SITE_URL
# を設定（実機は 127.0.0.1 ではなく LAN の IP を指定）
```

- テストユーザー: seed の たろう（Web でログイン確認済みのアカウント）

## シナリオ 1: オフライン作成 → 自動転送（US1 / SC-001〜003）

1. オンラインでログイン → 端末を**機内モード**にする
2. 「書く」からログを作成・保存（必須項目のみ）
   - **期待**: 通信エラーなしで保存完了。一覧に「転送待ち」バッジ付きで表示（SC-001）
3. アプリを強制終了 → 再起動（機内モードのまま）
   - **期待**: 転送待ちログが残っている（SC-007）
4. 機内モードを解除（アプリはフォアグラウンド）
   - **期待**: 1 分以内に自動転送が始まり「転送済み」へ。Web 版のログ一覧・ダッシュボード集計に反映（SC-002 / US1-AC3）
5. 冪等性: 機内モード⇄解除を転送中に繰り返す・手動再転送を連打する
   - **期待**: Web のログ件数は作成数と一致（二重登録 0 / SC-003）。SQL 確認: `select count(*) from dives where user_id='<たろう>'`
6. 失敗系: ローカル Supabase を停止した状態で転送 → 失敗理由の表示と手動再転送を確認（FR-006）

## シナリオ 2: 閲覧・全件同期（US2 / SC-004）

1. Web で作成済みのログが複数ある状態でモバイルにログイン（オンライン）
   - **期待**: 一覧に Web と同じログが新しい順で表示・詳細も閲覧可（US2-AC1）
2. 設定 →「オフライン用に同期」を実行 → 機内モード → 一覧・詳細を開く
   - **期待**: 全ログが閲覧できる（SC-004）。最終同期日時が表示される
3. 同期未実行の端末（アプリ再インストール）で機内モードにして一覧を開く
   - **期待**: 「オフラインで閲覧するには同期が必要」の案内（FR-013）
4. Web でログを 1 件編集 → モバイルをオンラインにして再同期
   - **期待**: 編集後の内容に更新される（FR-012）
5. 転送待ちログ + サーバー由来ログが混在する一覧で、状態バッジで区別できる（FR-014）

## シナリオ 3: エクスポート（US3 / SC-006）

1. オンラインで設定 → エクスポート（CSV）を実行
   - **期待**: ファイルが生成され共有シートが開く。内容の項目が Web 版 CSV と一致（SC-006）
2. PDF 形式でも同様に確認
3. 機内モードでエクスポートを実行
   - **期待**: 「エクスポートには通信が必要」の案内（エラー画面にしない / Q3）
4. 転送待ちログがある状態でエクスポート
   - **期待**: 対象外である旨と転送を促す案内（US3-AC3）

## シナリオ 4: 認証・データ保護（FR-018〜020）

1. Google ログインでも一連の操作ができる（FR-018）
2. セッション失効を再現（Supabase 側でセッション無効化）→ 転送待きログが保持され、再ログイン後に転送できる（FR-020 / SC-007）
3. ログアウト時に未転送ログがあると警告が出る。確認後は端末データが消える
4. 別ユーザーでログインすると、前ユーザーの転送待ち・キャッシュは見えない（FR-019）

## 自動テスト・静的チェック

```bash
npm run test --workspace packages/core         # スキーマ・変換（Vitest）
npm run test:unit --workspace mobile           # 純粋ロジック（DAL・状態機械・全件同期 = Vitest + node:sqlite）
npm run test:component --workspace mobile      # RN コンポーネント（jest-expo + RNTL）
npm run type-check --workspace mobile
npx biome check mobile packages/core           # lint / format
npm run test --workspace service-front         # re-export 化・エクスポートルート変更の回帰
```

Google ログインの事前設定（T029）: Supabase ダッシュボード → Authentication → URL Configuration の
Redirect URLs に、Expo の `makeRedirectUri()` が返す URL（開発時は `exp://<LAN IP>:8081` 系、
ビルド後は `mobile://`）を登録する。
