# Feature Specification: ログのエクスポート（PDF / CSV）

**Feature Branch**: `worktree-014-log-export`

**Created**: 2026-06-18

**Status**: Draft

**Input**: User description: "7. ログのエクスポート（PDF / CSV） — 紙ログ提出・バックアップ用途。todo のサブスク特典との相性も良いです"

## Clarifications

### Session 2026-06-18

- Q: PDF / エクスポートに写真を含めるか → A: PDF にはダイブごとの写真サムネイルを含める。CSV には写真を含めない
- Q: エクスポート機能を有料（サブスク）限定にするか → A: v1 はログイン中の全ユーザーが利用可。サブスク連携は将来対応
- Q: 個別ログ単位のエクスポートを可能にするか → A: 一括出力に加え、ダイブ詳細からの単一ログ出力と、一覧での複数選択出力の両方に対応する
- Q: 期間以外の絞り込み条件をエクスポートで使えるようにするか → A: 一覧（機能 013）の現在の検索・フィルタ条件を引き継いでエクスポートする

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ダイブログを CSV で一括バックアップ (Priority: P1)

ダイバーが自分の全ダイブログを 1 つの CSV ファイルとしてダウンロードし、表計算ソフトや他サービスへの移行・個人バックアップに利用する。

**Why this priority**: データ消失への不安を解消し、ユーザーが自分の記録を「持ち出せる」ことを保証する最も基礎的な価値。生成処理がもっとも単純で、これ単体でも実用的な MVP になる。

**Independent Test**: ログを数件登録したユーザーがエクスポート操作を行い、ダウンロードされた CSV をスプレッドシートで開いて、全ログ・全項目が文字化けなく正しい値で含まれていることを確認できる。

**Acceptance Scenarios**:

1. **Given** ログを 3 件持つユーザー, **When** CSV エクスポートを実行する, **Then** ヘッダー行 + 3 データ行（各ログ 1 行）の CSV ファイルがダウンロードされる
2. **Given** ログを 1 件も持たないユーザー, **When** CSV エクスポートを実行する, **Then** ヘッダー行のみの CSV がダウンロードされる（エラーにはならない）
3. **Given** 日本語のポイント名やメモを含むログ, **When** CSV をダウンロードして開く, **Then** 日本語が文字化けせず表示される
4. **Given** カンマや改行を含むメモ, **When** CSV を開く, **Then** 値が正しく 1 セルに収まり列がずれない

---

### User Story 2 - 紙ログ提出用の PDF を出力 (Priority: P2)

ダイバーがショップやインストラクターへの提出・対面確認のために、ログブック体裁で整形された PDF を出力して印刷・共有する。全件・絞り込み結果の一括出力に加え、ダイブ詳細画面から「その 1 本だけ」を PDF 出力できる。

**Why this priority**: 「紙ログ提出」という差別化用途を満たす。CSV より整形要件が高く実装コストが大きいため P2 とするが、本機能の主目的の 1 つ。

**Independent Test**: ログを持つユーザーが PDF エクスポートを実行し、生成された PDF を開いて、各ダイブの主要項目（番号・日付・ポイント・水深・潜水時間など）と写真サムネイルが読みやすいログブック体裁で並んでいることを確認できる。

**Acceptance Scenarios**:

1. **Given** ログを複数件持つユーザー, **When** PDF エクスポートを実行する, **Then** 各ダイブが整形されたログ欄として並んだ PDF がダウンロードされる
2. **Given** 写真が添付されたログ, **When** PDF を出力する, **Then** 各ダイブ欄にその写真のサムネイルが表示される
3. **Given** 写真が未添付のログ, **When** PDF を出力する, **Then** サムネイル領域は空欄として扱われ、レイアウトが崩れない
4. **Given** 任意項目が未入力のログ, **When** PDF を出力する, **Then** 未入力項目は空欄として表示され、レイアウトが崩れない
5. **Given** ダイブ詳細画面を開いたユーザー, **When** その 1 本の PDF 出力を実行する, **Then** 当該ダイブのみのログ欄が記載された PDF がダウンロードされる
6. **Given** PDF を印刷する, **When** A4 用紙に出力する, **Then** 各ダイブ欄が用紙からはみ出さず読める

---

### User Story 3 - 対象を絞ってエクスポート (Priority: P3)

ダイバーが「特定の旅行分だけ」「この数本だけ」のように、対象を絞り込んでから CSV / PDF を出力する。絞り込みは (1) ログ一覧（機能 013）で適用中の検索・フィルタ条件をそのまま引き継ぐ方式と、(2) 一覧で個別にログを複数選択する方式の 2 通りに対応する。

**Why this priority**: 全件ではなく必要な範囲だけ提出・共有したいニーズに応える利便性向上。P1/P2 が無くても価値が出る独立機能だが、まず全件出力が成立してからの追加で十分なため P3。

**Independent Test**: 複数期間・複数条件のログを持つユーザーが、一覧でフィルタを適用した状態でエクスポートし、出力ファイルにそのフィルタ結果のログだけが含まれることを確認できる。また一覧で特定の数件を選択してエクスポートし、選択分だけが含まれることを確認できる。

**Acceptance Scenarios**:

1. **Given** 一覧（機能 013）で 2025 年の期間フィルタを適用中のユーザー, **When** その状態でエクスポートする, **Then** フィルタ結果（2025 年）のログのみが出力に含まれる
2. **Given** 一覧で 3 件のログを選択したユーザー, **When** 選択分のエクスポートを実行する, **Then** 選択した 3 件のみが出力に含まれる
3. **Given** 絞り込み結果が 0 件, **When** エクスポートする, **Then** 「対象ログがない」旨が伝わり、空のヘッダーのみ／空の PDF を生成せず適切に案内される

---

### Edge Cases

- ログ件数が非常に多い（例: 数百〜千件超）場合でも、エクスポートが妥当な時間内に完了し、ファイルが破損しないか
- 写真添付（機能 012）があるログの扱い（PDF は写真サムネイルを含める / CSV は写真を含めない）。写真が複数枚・未添付・読み込み失敗の各ケースで PDF レイアウトが崩れないこと
- エクスポート処理中にユーザーが画面を離れた／二重に実行した場合の挙動
- 選択モードでログ表示領域をクリックした際、詳細画面へ遷移せず選択トグルのみが行われること（誤遷移しないこと）
- 他人のログが混入しないこと（本人のログのみが出力対象であること）
- 値に CSV の区切り文字・引用符・改行が含まれる場合のエスケープ
- 日付・時刻・小数（水深・温度など）の表記が一貫していること

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ログイン中のユーザーは、自分のダイブログを CSV 形式でダウンロードできなければならない
- **FR-002**: ログイン中のユーザーは、自分のダイブログを PDF 形式でダウンロードできなければならない
- **FR-003**: エクスポートには本人が所有するログのみを含め、他ユーザーのログを一切含めてはならない
- **FR-004**: CSV には先頭にヘッダー行を含め、1 ログを 1 行として、ダイブログの記録項目（番号・日付・時刻・ポイント・ダイブタイプ・コンディション・水深・潜水時間・装備/ガス・メモ等）を列として出力しなければならない
- **FR-005**: CSV はカンマ・引用符・改行を含む値を正しくエスケープし、表計算ソフトで列ずれなく開けなければならない。あわせて `= + - @` 始まりのセルは先頭に `'` を付けて数式として評価されないようにする（数式インジェクション対策。負数などの純粋な数値は対象外 / 2026-07-02）
- **FR-006**: CSV は日本語を含む文字を文字化けせず開けるエンコーディングで出力しなければならない
- **FR-007**: PDF は各ダイブを 1 つのログ欄として、主要項目を読みやすいログブック体裁で整形して出力しなければならない
- **FR-007a**: PDF は写真が添付されたダイブについて、当該写真のサムネイルをログ欄内に表示しなければならない。写真が無いダイブはサムネイル領域を空欄として扱い、レイアウトを崩してはならない（CSV には写真を含めない）
- **FR-008**: 任意項目が未入力のログでも、CSV では空値、PDF では空欄として出力し、エラーやレイアウト崩れを起こしてはならない
- **FR-009**: ログが 0 件のユーザーがエクスポートしても、エラーにならず適切に処理されなければならない（CSV はヘッダーのみ等）
- **FR-010**: ユーザーはログ一覧（機能 013）で適用中の検索・フィルタ条件を引き継いで、その結果に一致するログのみをエクスポートできなければならない
- **FR-010a**: ユーザーはダイブ詳細画面から、当該ダイブ単体を PDF / CSV でエクスポートできなければならない
- **FR-010b**: ユーザーはログ一覧で複数のログを選択し、選択したログのみをエクスポートできなければならない
- **FR-010c**: 選択モード中は各ログの詳細画面への遷移を無効化し、ログ表示領域全体のクリックで選択をトグルできなければならない（選択操作の範囲をチェックボックスに限定せず、誤って詳細画面へ遷移させない）
- **FR-010d**: エクスポート機能は、利用にあたって有料プラン（サブスク）への加入を必須としてはならない（v1 ではログイン中の全ユーザーが利用可能）
- **FR-011**: 出力ファイル名は内容と日付が判別できる命名（例: ログ種別と出力日を含む）でなければならない
- **FR-012**: エクスポート操作の結果（成功・対象0件・失敗）がユーザーに明確に伝わらなければならない
- **FR-013**: エクスポート機能は、ダイブログ一覧などログにアクセスできる画面から到達できなければならない

### Key Entities *(include if feature involves data)*

- **ダイブログ（dive）**: エクスポートの対象データ。1 ユーザーが複数保持。番号・日付・ポイント・水深・潜水時間などの記録項目を持つ（機能 002 で定義済みの既存テーブルを参照）。本機能は新規にデータを生成せず、既存ログを読み取って整形・出力する。
- **エクスポート設定（一時的な指定）**: 出力形式（CSV / PDF）と任意の絞り込み条件（期間など）。永続化はせず、エクスポート実行時の入力としてのみ扱う。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーはログ一覧から 2 ステップ以内（形式選択 → 実行）でエクスポートを開始できる
- **SC-002**: 100 件規模のログのエクスポート（CSV / PDF とも）が 10 秒以内に完了する
- **SC-003**: ダウンロードした CSV を主要な表計算ソフトで開いたとき、全ログ・全項目が列ずれ・文字化けなく表示される（検証時 100%）
- **SC-004**: 出力した PDF を A4 で印刷したとき、各ダイブ欄が用紙からはみ出さず判読できる
- **SC-005**: エクスポート結果に他ユーザーのログが混入する件数は 0 件である

## Assumptions

- 対象データは機能 002（ダイブログ CRUD）の既存 `dives` レコードであり、本機能はデータを読み取るのみで新規テーブルは追加しない前提
- PDF には写真（機能 012）のサムネイルを含めるが、CSV には写真を含めない（紙ログ提出時の見栄えと、バックアップ用途での軽量さを両立）
- todo に記載の「サブスク特典」との連携（有料プラン限定化など）は、課金/サブスク基盤が未実装のため v1 のスコープ外とし、本機能はログイン中の全ユーザーが利用できる前提とする
- 絞り込みエクスポートは機能 013（検索・フィルタ強化）の一覧条件を引き継ぐ方式を前提とし、エクスポート専用の絞り込み UI は別途設けない
- PDF のレイアウトは PADI 等のログブックを参考にした汎用的なログ欄体裁とし、特定団体の公式フォーマット完全準拠は v1 のスコープ外とする
- エクスポートはユーザー自身の操作起点（オンデマンド）で行い、定期自動バックアップやメール送信は v1 のスコープ外とする
- 文字エンコーディングや区切り文字など技術的詳細は plan 段階で確定する（本 spec では「文字化け・列ずれが起きないこと」を要件として規定）
