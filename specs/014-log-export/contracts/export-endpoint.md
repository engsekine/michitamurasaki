# Contract: エクスポートエンドポイント + CSV 列

`GET /dives/export`（Route Handler: `src/app/(authenticated)/dives/export/route.ts`）の I/O 契約と、CSV 列の正定義。実装・テストはこの契約を単一の正とする。

## エンドポイント

`GET /dives/export`

認証必須（`(authenticated)` グループ配下）。未認証はアプリ既定の認証フローへ。データ取得は本人 RLS 下のサーバークライアントで行う。

### クエリパラメータ

| 名前 | 必須 | 形式 / 許可値 | 説明 |
|---|---|---|---|
| `format` | YES | `csv` \| `pdf` | 出力形式。それ以外は `400` |
| `ids` | NO | カンマ区切り UUID（最大 500） | 出力対象ログ ID。指定時はフィルタ条件より優先 |
| `number` | NO | 整数 0〜9999 | 機能 013 と同一（`parseDiveFilter` で解析） |
| `date_from` | NO | `YYYY-MM-DD` | 潜水日の下限（含む） |
| `date_to` | NO | `YYYY-MM-DD` | 潜水日の上限（含む） |
| `depth_min` | NO | 数値 0〜300 | 最大水深の下限（含む。未記録は除外） |
| `depth_max` | NO | 数値 0〜300 | 最大水深の上限（含む。未記録は除外） |
| `type` | NO | `DIVE_TYPE_OPTIONS` の値 | ダイブタイプ |
| `q` | NO | 文字列（最大 120） | ポイント名（自由入力名 + サイト名に部分一致） |
| `buddy` | NO | UUID | バディ（登録ユーザー）の user_id。UUID 形式のみ採用（021 で追加。spec 021 FR-022） |
| `buddy_name` | NO | 文字列（最大 100） | バディ名（フリーテキスト・部分一致）（021 で追加） |

- 不正・範囲外のフィルタ値は当該パラメータのみ無視（013 と同じ寛容パース）。
- `ids` が UUID 形式に反する／501 件以上の場合は `400`（無言の丸めはしない）。

### 対象決定ロジック

1. `ids` 指定あり → その ID 群（本人分のみ）を対象。単一出力（1 件）も複数選択もこの経路。RLS は公開ログ（`is_public`）も可視のため、本人分の限定は RLS ではなく `ownerId` の明示絞り込み（`export-query.ts` の `eq('user_id', ownerId)`）で担保する。
2. `ids` なし → フィルタを適用して該当全件（フィルタ空＝全件）を対象。
3. いずれも `dive_date` 降順・`id` 降順で安定ソート。最大 500 件。

### レスポンス

| 状況 | ステータス | ヘッダー / ボディ |
|---|---|---|
| CSV 成功 | `200` | `Content-Type: text/csv; charset=utf-8`、`Content-Disposition: attachment; filename="<name>.csv"`、本文 = BOM + CSV |
| PDF 成功 | `200` | `Content-Type: application/pdf`、`Content-Disposition: attachment; filename="<name>.pdf"`、本文 = PDF バイト列 |
| 対象 0 件（CSV） | `200` | ヘッダー行のみの CSV（FR-009） |
| 対象 0 件（PDF） | `200` | 「対象ログがありません」の 1 ページ PDF（FR-009） |
| `format` 不正 / `ids` 不正 | `400` | エラーメッセージ（本文テキスト） |
| 未認証 | `401` | ミドルウェアで認証フローへ誘導するのが基本だが、Route Handler 側でも `auth.getUser()` で未認証を弾き `401` を返す（二重防衛） |
| 取得失敗等 | `500` | エラー（error 境界に委ねる） |

### ファイル名（`export-filename.ts`）

- パターン: `dive-logs_<YYYYMMDD>.<ext>`（全件・フィルタ時）
- 単一出力時（`ids` が 1 件）: `dive-log_<diveDate>_<安全化ポイント名>.<ext>`
- `<YYYYMMDD>` は出力日。日本語ポイント名は ASCII 安全化（不可文字を `_`）し、`filename*=UTF-8''` での付与も検討（実装で RFC 5987 を使用可）。

## CSV 列契約（正）

- エンコード: **UTF-8 + 先頭 BOM**
- 改行: `\r\n` / 区切り: `,` / 引用: 値に `,` `"` 改行を含む場合のみ `"` で囲み、内部 `"` は `""`
- 1 行目はヘッダー、以降 1 ダイブ 1 行、`dive_date` 降順
- 真偽（`certification_dive`）は `はい` / `空文字`
- `tank_type`: `aluminum`→`アルミ` / `steel`→`スチール` / null→空
- `location`: `diveLocationLabel`（自由入力名優先、なければサイト名）

列順（`data-model.md` の DiveExportRow と一致）:

```
ダイブ番号, 潜水日, エントリー時刻, エキジット時刻, ポイント, エリア, ダイブタイプ,
天気, 気温(℃), 水温(℃), 透明度(m), 波・うねり, 流れ,
最大水深(m), 平均水深(m), 潜水時間(分),
タンク種類, タンク容量(L), ガス種類, 酸素濃度(%), 開始残圧(bar), 終了残圧(bar), ウェイト(kg),
スーツ, 装備メモ, バディ, インストラクター, 講習ダイブ, メモ
```

## PDF レイアウト契約（要約）

- 用紙 A4・日本語フォント埋め込み（`Font.register`）
- 各ダイブ = 1 ログ欄。ヘッダーに番号・ポイント名、本文にラベル + 値で次の項目を整形（実装 `DiveLogPdf.tsx` の `fieldRows` と一致）: 日付 / ダイブタイプ / 潜水時間 / 最大水深 / 平均水深 / 水温 / 透明度 / 天気 / タンク / ガス / 残圧 / ウェイト / バディ / インストラクター、および メモ（全幅）
- 写真があれば欄内にサムネイル最大 4 枚（cover 優先）。無ければ欄を詰めて崩さない
- 欄が A4 をまたぐ場合は次ページへ送る（欄は分割しない方針）

## テスト観点（contract 由来）

- `format` 欠落/不正 → 400
- `ids` 不正形式・501 件 → 400
- `ids` 1 件 → 単一ファイル名、対象 1 件のみ
- フィルタ（`date_from`/`type` 等）→ 該当行のみ含む
- 0 件: CSV はヘッダーのみ / PDF は案内 1 ページ
- CSV: メモにカンマ・改行・`"` を含む行が列ずれしない、BOM 付与、日本語が保持される
- 本人以外の `ids` を混ぜても他人の行が出力されない（`ownerId` の明示絞り込み。RLS は公開ログも可視のため依拠しない）
