# Feature Specification: ブランク日数の表示

**Feature Branch**: `feature/009-blank-days`

**Created**: 2026-06-13

**Status**: Draft

**Input**: User description: "ブランク日数の表示 — 「最後に潜ってから ○日」を TOP に。ショップで毎回申告する値で、daysUntil"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - TOP でブランク日数を一目で確認する (Priority: P1)

ダイバーであるユーザーは、TOP（ダッシュボード）を開くだけで「最後に潜ってから何日経ったか（ブランク日数）」を一目で確認できる。ダイビングショップでは受付のたびに「最後に潜ったのはいつですか / ブランクはどのくらいですか」を申告するのが通例であり、ユーザーが自分で日数を数えなくても、申告にそのまま使える値として表示される。

**Why this priority**: ブランク日数はショップ申告で毎回使われる値であり、この表示単体で「アプリを開けば申告値がわかる」という価値が成立する。本機能の根幹。

**Independent Test**: 最後のダイブログの日付が 45 日前のユーザーで TOP を開き、ブランク日数として「45日」が表示されることで単独テスト可能。

**Acceptance Scenarios**:

1. **Given** 最後のダイブログの日付が 45 日前のユーザー, **When** TOP を開く, **Then** ブランク日数として「45日」が一目でわかる形で表示される
2. **Given** 当日のダイブログがあるユーザー, **When** TOP を開く, **Then** ブランク日数は「0日」と表示される（マイナスや空欄にならない）
3. **Given** ダイブログが 1 件もないユーザー, **When** TOP を開く, **Then** ブランクの統計パネルは値「—」で表示され（日数の誤表示はしない）、最近のログ欄には最初のログ記録を促す既存の案内が表示される
4. **Given** ブランク日数が表示されている状態, **When** 新しいダイブログを当日の日付で登録して TOP に戻る, **Then** ブランク日数が「0日」に更新されている

---

### Edge Cases

- ダイブログが 1 件もない場合 → ブランクの統計パネルは「—」表示（feat/design-change で FV 統計に統合）。最近のログ欄の「最初のログを記録しよう」案内は維持する
- 最後のダイブが当日の場合 → 「0日」と表示する（「今日もダイビング日和！」等の既存メッセージは維持してよい）
- 最後のダイブログの日付が未来日の場合（先日付で登録したログ）→ マイナス表示にせず「0日」として扱う
- 日付の基準はユーザーのローカル日付（日本時間）とし、深夜 0 時をまたぐと 1 日加算される（暦日差）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: TOP に、最後のダイブログの日付から現在までの経過日数（ブランク日数）を「○日」の形式で表示する
- **FR-002**: ブランク日数は登録済みダイブログの最新の日付から自動計算する。ユーザーが入力・更新する項目ではない
- **FR-003**: 最後のダイブが当日の場合は「0日」と表示する。計算結果が負になる場合（未来日のログ）も「0日」として扱い、マイナスを表示しない
- **FR-004**: ダイブログが 0 件の場合はブランク日数の値を出さない（FV 統計パネルは「—」表示）。既存のログ記録への案内は維持する
- **FR-005**: 経過日数はユーザーのローカル日付（日本時間）基準の暦日差で計算する（時刻は考慮しない）
- **FR-006**: ダイブログの追加・編集・削除後に TOP を表示すると、ブランク日数は最新のログ状態を反映する
- **FR-007**（feat/design-change で追加）: ブランク日数の右側に最終潜水日（`最終潜水日: YYYY/MM/DD`）を併記する。ログ 0 件時は表示しない

### Key Entities

- **ダイブログ（既存）**: ブランク日数の計算元。最新のダイブ日付のみを参照する。本機能による属性追加はない
- **ブランク日数**: 最新のダイブ日付から現在日までの経過日数（暦日差・最小 0）。導出値であり保存しない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは TOP を開くだけ（追加操作 0 回）でブランク日数を確認できる
- **SC-002**: 表示されるブランク日数が、最新のダイブログの日付に基づいて 100% 正しい（手計算との不一致 0 件）
- **SC-003**: ログ 0 件・当日ダイブ・未来日ログのいずれの状態でも、マイナス値や空欄などの破綻した表示が発生しない

## Assumptions

- 「TOP に表示」は、既存 TOP ヒーローの「前回のダイブから ○ 日」という文章表現を、ショップ申告にそのまま使える明示的な「ブランク ○日」の数値表示として強化・置き換えする解釈とした（表示位置の詳細レイアウトは設計フェーズで確定する）
- **feat/design-change（2026-07-08）**: 専用コンポーネント `BlankDays` は削除され、FV ヒーロー（`DashboardHero`）の統計 4 項目の 1 つ「ブランク」として統合された。計算ロジック（`calcBlankDays`）と `getDashboardHero` はそのまま利用し、最終潜水日（`lastDiveOn`）の併記が追加された。画面仕様は [003 screens/top.md](../003-dashboard/screens/top.md) を参照
- 表示単位は「日」のみとする（「○ヶ月」「○週間」への変換・併記はスコープ外）
- ブランク日数の計算元は登録済みダイブログの最新日付であり、ログに記録されていないダイビングは考慮しない
- リフレッシュ講習の推奨など、ブランク日数に応じた警告・通知はスコープ外とする（将来の拡張余地）
- 既存の認証機能とダイブログ機能（002-dive-log-crud）が利用できることを前提とする
