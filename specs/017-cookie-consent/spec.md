# Feature Specification: Cookie 同意バナー

**Feature Branch**: `017-cookie-consent`

**Created**: 2026-06-25

**Status**: Draft

**Input**: User description: "cookie同意ボタンの実装"

## Clarifications

### Session 2026-06-25

- Q: Cookie 同意の粒度は? → A: 一括の「同意 / 拒否」のみ（必須は常時オン、非必須はまとめて可否）
- Q: 同意管理の対象となる非必須 Cookie の範囲は? → A: 現状は非必須 Cookie なし（必須=認証セッション等のみ）。バナーと同意状態の記録・制御の「枠組み」だけ用意し、将来非必須 Cookie を追加したときにその枠で制御する
- Q: バナーの操作モデル（ブロッキング有無）は? → A: 非ブロッキング（画面下部などの帯）。選択前もサイトを閲覧でき、選ぶまでバナーが出続ける
- Q: 「閉じる(×)」ボタンの有無と意味は? → A: 独立した閉じるボタンは設けない。操作は「同意」「拒否」「ポリシーリンク」のみで、選ぶまでバナーは残る

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 初回訪問で同意/拒否を選べる (Priority: P1)

サイト訪問者として、初めてアクセスしたときに Cookie の利用について説明するバナーが表示され、「同意する」「拒否する」を選んで操作を続けたい。

**Why this priority**: 同意取得の入口そのもの。これが無いと非必須 Cookie の利用可否をユーザーが決められず、機能が成立しない最重要ストーリー。

**Independent Test**: Cookie 未選択のブラウザでサイトを開き、バナーが表示され、「同意する」または「拒否する」を押すとバナーが閉じてサイトを継続利用できることを確認すれば単独で検証できる。

**Acceptance Scenarios**:

1. **Given** Cookie 同意の記録が無い訪問者がいずれかのページを開いている、**When** ページが表示される、**Then** システムは Cookie 利用の説明とプライバシーポリシーへのリンクを含む同意バナーを表示する
2. **Given** 同意バナーが表示されている、**When** 訪問者が「同意する」を押す、**Then** システムは同意を記録しバナーを閉じる
3. **Given** 同意バナーが表示されている、**When** 訪問者が「拒否する」を押す、**Then** システムは拒否を記録しバナーを閉じる
4. **Given** 同意バナーが表示されている、**When** 訪問者がプライバシーポリシーのリンクを押す、**Then** システムはプライバシーポリシー（`/privacy-policy`）を開く

---

### User Story 2 - 選択を保存し再表示しない (Priority: P1)

訪問者として、一度同意/拒否を選んだら次回以降は同じ選択が引き継がれ、毎回バナーが出ないでほしい。

**Why this priority**: 毎回バナーが出ると利用体験を著しく損なう。US1 と一体で「一度選べば済む」状態を成立させるため P1。

**Independent Test**: 一度「同意する」を押した後にページを再読み込み・別ページへ遷移し、バナーが再表示されないことを確認すれば単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 訪問者が前回「同意する」または「拒否する」を選んでいる、**When** 再訪問または別ページへ遷移する、**Then** システムはバナーを表示しない
2. **Given** 保存された同意の有効期限が切れている、**When** 訪問者がアクセスする、**Then** システムは改めて同意バナーを表示する

---

### User Story 3 - 拒否時は非必須 Cookie を使わない (Priority: P1)

訪問者として、「拒否する」を選んだ場合は、サイトの動作に必須でない Cookie（解析・計測など）が自分のブラウザに保存・利用されないようにしたい。

**Why this priority**: 同意ボタンの実効性そのもの。拒否しても非必須 Cookie が動くなら同意取得の意味が無く、コンプライアンス上も問題になるため P1。

**Independent Test**: 「拒否する」を選んだ状態で、非必須 Cookie が保存されないこと、「同意する」を選んだ状態でのみ保存されることを確認すれば単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 訪問者が「拒否する」を選んでいる、**When** サイトを利用する、**Then** システムは必須 Cookie（ログインセッション等）のみを使い、非必須 Cookie を保存・利用しない
2. **Given** 訪問者が「同意する」を選んでいる、**When** サイトを利用する、**Then** システムは非必須 Cookie の保存・利用を許可する
3. **Given** 訪問者がまだ選択していない（バナー表示中）、**When** サイトを閲覧している、**Then** システムは非必須 Cookie を保存・利用しない（同意前はオプトイン扱い）

---

### User Story 4 - 後から選択を変更できる (Priority: P3)

訪問者として、一度行った同意/拒否の選択を、後からいつでも変更できるようにしたい。

**Why this priority**: 同意の撤回・変更手段は望ましいが、初回の同意取得（US1〜US3）が成立した後でも価値を損なわない。

**Independent Test**: 選択済みの状態で、フッター等の「Cookie 設定」導線から再びバナー/設定を開き、選択を変更して保存できることを確認すれば単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 訪問者が既に選択済みである、**When** フッターの「Cookie 設定」導線を押す、**Then** システムは同意バナー/設定を再表示し選択を変更できる
2. **Given** 訪問者が設定を変更して保存した、**When** 保存が完了する、**Then** システムは新しい選択を記録し以降の Cookie 利用に反映する

---

### Edge Cases

- ブラウザが Cookie / ストレージを無効化している場合 → 選択を保存できないため、毎回バナーを表示する（必須 Cookie が使えない場合の挙動は劣化を許容）
- 保存された同意が有効期限切れの場合 → 改めて同意バナーを表示する
- 同意前のページ表示で画面のちらつき（バナーの遅延表示）が起きないこと
- キーボードのみ・スクリーンリーダー利用時もバナーの操作（同意/拒否/ポリシーリンク）が完結できること（独立した「閉じる(×)」操作は設けない）
- ログイン状態に関わらず（未ログイン訪問者でも）バナーが機能すること
- 同意取得の前後で、ログインセッション等の必須 Cookie は常に維持されること

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは Cookie 同意の記録が無い訪問者に対し、いずれのページでも Cookie 利用の説明・プライバシーポリシーへのリンク・「同意する」「拒否する」を含む同意バナーを表示しなければならない
- **FR-002**: システムは訪問者が「同意する」を選んだとき、同意を記録しバナーを閉じなければならない
- **FR-003**: システムは訪問者が「拒否する」を選んだとき、拒否を記録しバナーを閉じなければならない
- **FR-004**: システムは記録済みの選択がある訪問者に対し、再訪問・ページ遷移時にバナーを再表示してはならない
- **FR-005**: システムは同意/拒否の選択をブラウザに永続化し、選択には有効期限を設けなければならない。有効期限が切れた場合は改めて同意を求めなければならない
- **FR-006**: システムは「拒否」または「未選択（同意前）」の状態では、必須 Cookie 以外（非必須 Cookie）を保存・利用してはならない
- **FR-007**: システムは「同意」状態でのみ非必須 Cookie の保存・利用を許可しなければならない
- **FR-008**: システムはログインセッション等の必須 Cookie を、同意状態に関わらず常に利用できなければならない
- **FR-009**: システムは訪問者が後から選択を変更できる導線（フッター等の「Cookie 設定」）を提供し、そこから同意バナー/設定を再表示できなければならない
- **FR-010**: システムは未ログイン訪問者・ログインユーザーのいずれに対してもバナーを機能させなければならない
- **FR-011**: システムはバナー表示時に画面のちらつき（同意前コンテンツの一瞬の表示や大きなレイアウトシフト）を起こさず、キーボード操作・スクリーンリーダーで全操作（同意/拒否/リンク）を完結できるようにしなければならない
- **FR-014**: システムは同意バナーを**非ブロッキング**（画面下部などの帯）で表示し、選択前でも訪問者がサイトのコンテンツを閲覧・操作できるようにしなければならない。背後の操作を遮るモーダルにはしない（選択するまでバナーは表示し続ける）
- **FR-015**: システムは同意バナーの操作を「同意する」「拒否する」「プライバシーポリシーへのリンク」のみとし、選択を伴わない独立した「閉じる(×)」操作を設けてはならない
- **FR-012**: システムは同意の粒度を「全体一括」とし、必須 Cookie は常時許可・非必須 Cookie はまとめて「同意 / 拒否」する方式で提供しなければならない（用途カテゴリ別の個別トグルは設けない）
- **FR-013**: システムは「必須 Cookie＝認証セッション等のみ」「非必須 Cookie＝現状なし」を前提とし、同意状態の記録と非必須 Cookie の制御を行う**枠組み**を用意しなければならない。将来非必須 Cookie（アクセス解析等）を追加する際は、同意状態に応じて保存・利用を制御できる状態にしておくこと（追加される非必須 Cookie 自体の導入は本フェーズ対象外）

### Key Entities *(include if feature involves data)*

- **同意状態（consent）**: 訪問者ごとの選択。値は「同意 / 拒否」、選択日時、有効期限を持つ。ブラウザ側に保存される
- **Cookie カテゴリ**: 「必須（認証セッション等・常時許可）」と「非必須（同意が必要）」の区分。**現状の非必須は空**で、将来追加されるものを同意状態に応じて制御する枠組みを持つ

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Cookie 未選択の訪問者がサイトを開いたとき、同意バナーが表示され、追加の説明なしに「同意/拒否」を選んで操作を継続できる
- **SC-002**: 一度選択した訪問者には、再訪問・ページ遷移時にバナーが再表示されない（有効期限内）
- **SC-003**: 「拒否」または「未選択」状態では、非必須 Cookie が 100% 保存・利用されない（ブラウザの Cookie/ストレージ確認で 0 件）。現状は非必須 Cookie が無いため、制御の枠組み（同意状態に応じて非必須 Cookie の読み込みを抑止できること）をテスト用のダミー/将来追加分の想定で検証する
- **SC-004**: 同意取得フローの全受け入れ条件（表示・記録・再表示しない・非必須 Cookie の制御・設定変更）が E2E テストで再現・合格する
- **SC-005**: 同意バナーが WCAG 2.1 AA を満たす（キーボードのみで全操作可能、コントラスト基準、スクリーンリーダーで内容と操作が伝わる）

## Assumptions

- プライバシーポリシーは既存ページ `/privacy-policy` を参照する
- ログインセッション等の認証 Cookie は「必須（strictly necessary）」として同意なしに常時利用できる前提とする（同意の対象外）
- 現状この製品に非必須 Cookie は存在しない。本フェーズはバナー UI と同意状態の記録・制御の枠組みを用意するのが主目的で、制御対象の非必須 Cookie 自体は将来追加される想定
- 同意/拒否の選択はブラウザ側（Cookie もしくはローカルストレージ）に保存し、サーバー DB には保存しない（v1 ではユーザー横断の同意管理は対象外）
- 同意の有効期限は業界慣行に従い既定で 12 か月とする（FR-005。確定値は実装時に調整可）
- 対象地域・準拠法（GDPR / 改正電気通信事業法 等）の厳密な要件確定は本仕様の範囲外とし、一般的なオプトイン方式（同意前は非必須 Cookie を使わない）を採用する
- 以下は本フェーズの対象外とする:
  - 同意ログのサーバー保存・監査証跡
  - 第三者同意管理プラットフォーム（CMP）の導入
  - 多言語対応（日本語のみ）
