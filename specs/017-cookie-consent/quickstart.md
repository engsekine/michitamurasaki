# Quickstart: Cookie 同意バナー

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md)

バナーの表示・記録・再表示しない・gating・a11y をローカルで検証する手順。実装コードは含めない（タスクは `/speckit-tasks` で生成）。DB・Supabase の追加準備は不要。

## 前提

- service-front を起動できること（`npm run dev` もしくは Docker dev）
- 追加の環境変数・マイグレーションは不要

## 検証シナリオ

### シナリオ A: 初回表示と同意（US1 / US2 / P1）

1. ブラウザの `cookie-consent` Cookie を削除（または新規シークレットウィンドウ）して任意のページを開く
2. **期待**: 画面下部に非ブロッキングのバナー（説明 + プライバシーポリシーリンク + 「同意する」「拒否する」）が表示される。背後のページは操作できる
3. 「同意する」を押す
4. **期待**: バナーが消える。`cookie-consent=accepted` が Max-Age 付きで保存される
5. ページを再読み込み／別ページへ遷移
6. **期待**: バナーは**再表示されない**（FR-004 / SC-002）。再読み込み時に一瞬もバナーがちらつかない（FR-011）

### シナリオ B: 拒否（US1 / US3 / P1）

1. Cookie を削除して再アクセス → バナー表示 → 「拒否する」を押す
2. **期待**: バナーが消え `cookie-consent=rejected` が保存される。再訪問で再表示されない

### シナリオ C: 非必須 Cookie の gating（US3 / SC-003）

1. 現状、非必須 Cookie は存在しないため、テスト用のダミー被ゲート処理（`getCookieConsentClient()==='accepted'` を確認してから走るフラグ）で検証する
2. **期待**:
   - 「拒否」または「未選択」状態 → ダミー処理は走らない・非必須 Cookie は 0 件（ブラウザの Application タブで確認）
   - 「同意」状態 → ダミー処理が走る
3. 認証セッション等の必須 Cookie は、いずれの状態でも維持されている（FR-008）

### シナリオ D: 後から設定変更（US4）

1. 同意/拒否済みの状態でフッターの「Cookie 設定」を押す
2. **期待**: バナーが再表示され、選択を変更して保存できる（FR-009）

### シナリオ E: 期限切れ・Cookie 無効（Edge Cases）

1. `cookie-consent` Cookie を手動削除（期限切れ相当）→ 再アクセス
2. **期待**: 改めてバナーが表示される（FR-005）
3. （任意）ブラウザで Cookie を無効化 → アクセス
4. **期待**: 保存できないため毎回バナーが表示される（劣化を許容）

### シナリオ F: アクセシビリティ（SC-005）

1. キーボードのみでバナーの「同意する」「拒否する」「ポリシーリンク」に到達・操作できる（フォーカストラップが無く背後にも出られる）
2. axe（Playwright）でバナー表示状態の WCAG 2.1 AA 違反がゼロ

## 完了の目安

- シナリオ A〜F が手動 / E2E で再現・合格する
- 既存ページ（公開・認証）の表示・既存 a11y テストが回帰していない
