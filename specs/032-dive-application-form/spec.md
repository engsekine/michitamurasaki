# Feature Specification: ダイビング申し込みシートのテキスト出力

**Feature Branch**: `032-dive-application-form`

**Created**: 2026-07-10

**Status**: Draft

**Input**: User description: "ダイビング申し込みの時に入力を依頼される文章出力を実装したい（お名前・年齢・生年月日・性別・携帯電話・緊急連絡先・最寄りの駅・ライセンスランク・経験本数・伊豆千葉でのダイビング経験・ボートダイビング経験・最終ダイブ年月・ドライスーツ経験・ドライ経験本数・レンタル器材の有無と品目選択・スーツレンタル時の身長/体重/足のサイズ・コンタクトレンズ有無と種類・度付きマスクレンタル有無 を含む定型フォーマット）"

## Clarifications

### Session 2026-07-10

- Q: レンタル器材「無」のとき、品目一覧・サイズ欄を出力から省略するか空欄のまま全文出力するか？ → A: 省略するかどうかをユーザーがトグルで選べる（デフォルトは全文出力・空欄のまま）
- Q: 入力内容の保存（P3）は明示操作か自動か？ → A: 「保存」ボタンによる明示的な保存とする
- Q: 作成画面へのアクセス経路は？ → A: 独立ページを新設し、TOP ダッシュボードに導線を置く
- Q: 保存対象の範囲は？ → A: 個人属性のみ保存（氏名・電話・緊急連絡先・駅・身長体重足サイズ・コンタクト情報など）。レンタル品目の選択・省略トグルは保存せず毎回リセット

### Session 2026-07-11

- Q: シートを複数保存できるようにするか？ → A: 名前を付けて複数保存し、一覧から選択・削除できるようにする（1 ユーザー 20 件まで）
- Q: 複数保存時の保存範囲は？ → A: フォーム全体のスナップショット（レンタル品目の選択・省略トグルも含む）へ変更
- Q: 既存の保存データ（application_profiles・1 ユーザー 1 件）は？ → A: 未リリースのため移行せずテーブルごと置き換える
- Q: レンタル器材の有無のデフォルトは？ → A: 「無」をデフォルト選択とし、「無」が選択されたら省略トグルを自動で ON にする（手動で OFF に戻せる）
- Q: 基本情報（氏名〜最寄りの駅）の扱いは？ → A: 専用の「基本情報を保存」ボタンで 1 ユーザー 1 件保存し、新規シート作成時に自動入力する
- Q: 経験（ライセンスランク・経験本数・最終ダイブ年月・ドライスーツ経験/本数）も基本情報に含めるか？ → A: 含めて保存する。新規テーブルは application_sheets の 1 つに統合（基本情報は kind='base' の行）
- Q: 伊豆・千葉でのダイビング経験・ボートダイビング経験は？ → A: 項目ごと削除（フォーム・出力・DB から廃止）
- Q: 最終ダイブ年月の入力形式は？ → A: 「2026年7月」形式のテキスト入力にする
- Q: ドライスーツの経験本数は？ → A: ドライスーツの経験「有」を選んだときだけ入力欄を表示する

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 申し込みシートを作成してコピーする (Priority: P1)

ダイビングショップへの申し込み時、ショップから「お名前（ ）・年齢（ 歳）…」のような定型の記入依頼テキストが送られてくる。ユーザーはアプリの申し込みシート作成画面を開き、各項目をフォームで入力すると、ショップに送る定型フォーマットのテキストが生成される。生成されたテキストをワンタップでコピーし、メールや LINE にそのまま貼り付けて返信できる。

**Why this priority**: この機能の中核価値。スマホで定型文の（ ）を1つずつ編集して埋める手間をなくし、入力→整形済みテキスト取得→コピーまでを完結させる。これ単体で MVP として成立する。

**Independent Test**: 画面で全項目（または一部項目）を入力し、生成テキストが定型フォーマット通りであること・コピーできることを確認すれば単体でテスト可能。

**Acceptance Scenarios**:

1. **Given** ログイン済みユーザーが申し込みシート作成画面を開いている, **When** 氏名・年齢などの項目を入力する, **Then** 入力内容が反映された定型フォーマットのテキストがプレビューされる
2. **Given** 一部の項目が未入力のまま, **When** テキストを生成する, **Then** 未入力の項目は元の依頼文と同様に空欄（例: 「お名前（ ）」）のまま出力され、生成自体は妨げられない
3. **Given** 生成テキストが表示されている, **When** コピー操作をする, **Then** テキスト全文がクリップボードにコピーされ、コピー完了が視覚的に通知される
4. **Given** レンタル器材「有」を選択している, **When** レンタルしたい品目（ウエットスーツフルセット〜水中カメラ）を選択する, **Then** 選択した品目に ○ が付いた形で出力される
5. **Given** 画面を開いた直後（レンタル器材はデフォルトで「無」・省略トグル ON）, **When** テキストを生成する, **Then** 品目一覧〜度付きマスクのブロックが省略され「・レンタル器材（無）」で終わる
6. **Given** レンタル器材「無」を選択している, **When** 「未該当ブロックを省略する」トグルを外す, **Then** 品目一覧・身長/体重/足のサイズの記入欄・コンタクトレンズの有無（種類含む）・度付きマスクレンタルの要否も空欄のまま全文出力される
7. **Given** 生成テキストが表示されている, **When** 出力欄のテキストを直接編集する, **Then** 編集後の内容が保持され（フォーム変更で上書きされない）、コピーには編集後の内容が反映される。「フォームの内容から再生成」でフォーム由来の出力に戻せる

---

### User Story 2 - 登録済みデータからの自動入力 (Priority: P2)

ユーザーがすでにアプリへ登録しているプロフィール（氏名・生年月日・性別・身長・体重）、保有資格（ライセンスランク）、ダイブログ（経験本数・最終ダイブ年月）などのデータが、シート作成画面を開いた時点で該当項目に自動で入力されている。ユーザーはアプリが持っていない項目（携帯電話・緊急連絡先・最寄りの駅など）だけを入力すればよい。

**Why this priority**: アプリに蓄積したデータを活かす差別化ポイント。ただし P1（手入力での生成・コピー）だけでも価値が成立するため P2 とする。

**Independent Test**: プロフィール・資格・ダイブログを登録済みのユーザーで画面を開き、該当項目に登録値が初期表示されることを確認すれば単体でテスト可能。

**Acceptance Scenarios**:

1. **Given** プロフィール登録済みのユーザー, **When** 申し込みシート作成画面を開く, **Then** 氏名・生年月日・年齢（生年月日から算出）・性別・身長・体重が自動入力されている
2. **Given** 保有資格を登録済みのユーザー, **When** 画面を開く, **Then** ライセンスランクに登録済み資格のランクが自動入力されている
3. **Given** ダイブログを記録済みのユーザー, **When** 画面を開く, **Then** 経験本数にログ件数由来の本数、最終ダイブ年月に最新ログの年月が自動入力されている
4. **Given** 自動入力された項目, **When** ユーザーが値を修正する, **Then** 修正後の値が出力テキストに反映される（自動入力は上書き可能）
5. **Given** 該当データを未登録のユーザー, **When** 画面を開く, **Then** その項目は空欄のまま表示され、エラーにはならない

---

### User Story 3 - シートの複数保存と再利用 (Priority: P3)

ユーザーはフォームの入力内容全体（レンタル品目の選択を含むスナップショット）に名前を付けて複数保存できる。次回訪問時は保存済みシートの一覧から選ぶと全項目が復元され、ショップごと・用途ごとに申込内容を使い分けられる。不要になったシートは一覧から削除できる。

**Why this priority**: 2回目以降の利用体験を大きく改善するが、初回利用（P1・P2）が成立していることが前提のため P3 とする。

**Independent Test**: 名前を付けて保存 → 再訪問して一覧から選択し全項目が復元されること・削除で一覧から消えることを確認すれば単体でテスト可能。

**Acceptance Scenarios**:

1. **Given** フォームを入力したユーザー, **When** シート名を付けて保存し再訪問して一覧から選択する, **Then** レンタル品目の選択を含む全項目が復元されている
2. **Given** 保存済みシートを開いている状態, **When** 値を変更して上書き保存する, **Then** 次回は最新の値が復元される
3. **Given** 複数のシートを保存したユーザー, **When** 一覧を表示する, **Then** シート名と更新日時が更新順に並び、選択して切り替えられる
4. **Given** 保存済みシートがある状態, **When** 一覧の削除を実行し確認する, **Then** シートが削除され一覧から消える（開いていたシートを消した場合は新規作成状態に戻る）

---

### Edge Cases

- ダイブログが 0 件のユーザー: 経験本数・最終ダイブ年月は空欄のまま表示・出力される
- 保有資格が複数あるユーザー: 最上位（または最新）の資格ランクを自動入力し、ユーザーが修正できる
- プロフィール項目（生年月日・性別）が未登録: 該当項目は空欄となり、手入力できる
- レンタル「有」だがスーツ系の品目を選ばない場合: 身長/体重/足のサイズは記入不要（空欄で出力）
- コンタクトレンズ「無」の場合: 種類（ハード/ソフト/使い捨て）は出力上空欄となる
- 非常に長い入力値（駅名・氏名など）: 出力テキストが崩れず全文が含まれる
- クリップボードが利用できない環境: テキスト全文が選択可能な状態で表示され、手動コピーできる

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはログイン済みユーザーに対し、ダイビング申し込みシート作成画面を独立ページとして提供し、TOP ダッシュボードからの導線を表示しなければならない
- **FR-002**: システムは以下の項目を入力できるフォームを提供しなければならない: 氏名 / 年齢 / 生年月日（西暦） / 性別 / 携帯電話 / 緊急連絡先（続柄・電話番号） / 最寄りの駅 / ライセンスランク / 経験本数 / 最終ダイブ年月（「2026年7月」形式のテキスト入力） / ドライスーツ経験（有・無） / ドライスーツ経験本数（約。「有」選択時のみ表示） / レンタル器材の有無 / レンタル品目の選択 / 身長・体重・足のサイズ / コンタクトレンズの有無と種類（ハード・ソフト・使い捨て） / 度付きマスクレンタルの要否（伊豆・千葉でのダイビング経験・ボートダイビング経験は 2026-07-11 に廃止）
- **FR-003**: レンタル品目は次の選択肢を提供しなければならない: ウエットスーツフルセット / ドライスーツフルセット / マスク・スノーケル / フィン / グローブ / ブーツ / ウエットスーツ / ウエットベスト / ドライスーツ / BC / レギュレーター / ダイビングコンピューター / 水中ライト / 水中カメラ
- **FR-004**: システムは入力内容から、ショップの依頼文と同じ並び・体裁の定型テキスト（「・お名前（ ）」「・年齢（ 歳）」…の形式。選択したレンタル品目には ○ 付き）を生成しなければならない
- **FR-005**: 未入力項目は空欄（（ ）のまま）として出力し、全項目の入力を必須としてはならない
- **FR-006**: ユーザーは生成テキスト全文をワンタップでクリップボードにコピーでき、コピー完了のフィードバックを受け取れなければならない
- **FR-007**: システムは登録済みデータを対応する項目へ自動入力しなければならない: 氏名・生年月日・性別・身長・体重（プロフィール）/ 年齢（生年月日から算出）/ ライセンスランク（保有資格）/ 経験本数（ダイブログ件数）/ 最終ダイブ年月（最新ダイブログの年月）。保存済みの基本情報（FR-014）がある場合はプロフィール由来の値より優先する
- **FR-008**: 自動入力された値はユーザーが上書き修正でき、出力には修正後の値を反映しなければならない
- **FR-009**: 自動入力元のデータが未登録の場合も画面はエラーなく表示され、該当項目は空欄となる
- **FR-010**: システムはユーザーが「保存」操作を行ったときにシート名付きでフォーム全体のスナップショット（レンタル品目の選択・省略トグルを含む）を保存し、保存済みシートの一覧（名前・更新日時・更新順)から選択して全項目を復元できなければならない（自動保存はしない。ユーザー本人のみが自分の保存内容にアクセスできる）。シートは 1 ユーザーにつき複数保存でき（上限 20 件）、上書き保存・一覧からの削除ができる。シート名は必須（50 文字以内）
- **FR-011**: レンタル器材「無」の場合、品目選択・身長・体重・足のサイズ・コンタクトレンズの有無と種類・度付きマスクレンタルの要否の入力は求められない（入力欄を表示しない）
- **FR-012**: レンタル器材の有無はデフォルトで「無」を選択済みとする。「無」が選択されると「未該当ブロックを省略する」トグルが自動で ON になり、品目一覧・サイズ欄・コンタクトレンズの有無（種類含む）・度付きマスクレンタルの要否のブロックを出力から省略する。トグルは手動で OFF に戻せ、その場合は全文を空欄のまま出力する
- **FR-013**: ユーザーは生成テキストを出力欄で直接編集できなければならない。手動編集後はフォーム変更による再生成で上書きせず、明示的な「フォームの内容から再生成」操作でフォーム内容から作り直せる。コピー（FR-006）は編集後の内容を対象とする。編集内容は保存対象外（画面を離れると破棄される）
- **FR-014**: ユーザーは基本情報（氏名・年齢・生年月日・性別・携帯電話・緊急連絡先・最寄りの駅）と経験（ライセンスランク・経験本数・最終ダイブ年月・ドライスーツ経験/本数）を専用の「基本情報を保存」操作で保存でき（1 ユーザー 1 件・上書き）、新規シート作成時に資格・ログ・プロフィール由来の自動入力より優先して反映されなければならない

### Key Entities *(include if feature involves data)*

- **申し込みシート（Application Sheet）**: ユーザーが名前を付けて保存するフォーム全体のスナップショット（1 ユーザー N 件・上限 20 件）。氏名・年齢・生年月日などの自動入力の上書き値から、レンタル品目の選択・省略トグルまで全項目を保持する。ユーザーに帰属し本人のみ参照・更新・削除できる
- **基本情報（Base Profile）**: ユーザー 1 人につき 1 件保存する基本情報 + 経験の入力値。申し込みシートと同じテーブル（kind='base' の行・一覧非表示）で保持し、新規シート作成時の自動入力に使う（FR-014）
- **自動入力ソース（既存データ）**: プロフィール（氏名・生年月日・性別・身長・体重）、保有資格（ランク）、ダイブログ（件数・最新日付）。本機能では参照のみで変更しない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 登録済みデータがあるユーザーは、5 分以内に申し込みテキストの作成からコピーまで完了できる
- **SC-002**: 依頼文サンプルの項目（レンタル品目 14 種を含む全 17 項目。伊豆・千葉/ボート経験は廃止）が、生成テキストに漏れなく含まれる
- **SC-003**: 登録済みデータを持つユーザーの場合、手入力が必要な項目数が全体の半分以下になる
- **SC-004**: 2 回目以降の利用では、保存済みシートを一覧から選ぶだけで再入力なしに 1 分以内でテキストを再生成できる

## Assumptions

- 「お名前」はプロフィールに登録済みの姓名を自動入力する（ニックネームは使わない）。身長・体重もプロフィール登録値を自動入力し、修正は出力にのみ反映する（プロフィール自体は変更しない）
- 携帯電話はアプリに申し込み用途で使える登録が無いため手入力とする
- 出力フォーマットはユーザー提供の依頼文サンプルを標準形とし、ショップごとのフォーマット差異への対応（テンプレート編集機能）はスコープ外とする
- ドライスーツ経験・本数は、ログからの確実な導出が難しいため v1 では手入力とする（将来の自動導出は拡張余地）
- 経験本数はアプリ記録前のダイブ本数を含まない可能性があるため、自動入力後にユーザーが修正できることを前提とする
- 出力はプレーンテキストとし、メール・LINE 等への貼り付けで崩れない体裁とする
- 本機能はログイン済みユーザー向けとする（既存データの自動入力・保存が前提のため）
- 緊急連絡先等の個人情報を保存するため、保存内容は本人のみがアクセスできること（既存機能と同等のアクセス制御）を前提とする
