# Feature Specification: ダイブログへの写真添付

**Feature Branch**: `012-photo-attachments`

**Created**: 2026-06-16

**Status**: Draft

**Input**: User description: "写真添付 — ログアプリの体感価値を最も上げる定番機能で、既存の公開ページ（publicSlug）との相乗効果もある"

## 概要

ダイバーが 1 本ごとのダイブログに水中・水面の写真を添付し、後から振り返れるようにする。さらに既存の公開ログページ（[`specs/002-dive-log-crud/`](../002-dive-log-crud/spec.md) の `public_slug` / 公開機能）と組み合わせることで、公開ログに写真を載せて他のダイバーや友人と「潜った海の景色」を共有できる。テキストだけのログに比べ、ログを見返す体験価値・公開ログの訴求力を大きく高めることが狙い。

## Supporting Documents

- 関連機能: [`specs/002-dive-log-crud/`](../002-dive-log-crud/spec.md)（ダイブログ CRUD・公開機能の `is_public` / `public_slug`）

## Clarifications

### Session 2026-06-16

- Q: 受け付ける画像形式（特に HEIC）の扱い → A: HEIC を含め受け入れ、保存時に表示可能形式（JPEG/WebP）へ変換する
- Q: 位置情報（GPS EXIF）の除去範囲 → A: アップロード（変換）時に位置情報を常時除去する（保存 1 系統・公開非公開を問わず除去）
- Q: 添付枚数・1 ファイル容量の上限値 → A: 1 ログ最大 10 枚 / 1 ファイル最大 10MB（上限は変換前の入力ファイルに対する値）

### Session 2026-06-17（実装に伴う UI 決定。実装を真とし spec へ反映）

- Q: 写真の拡大表示 UI → A: 詳細画面ではサムネイル一覧を表示し、クリックするとモーダル（拡大表示）で大きく閲覧する（別タブ遷移にはしない）
- Q: 写真削除の UI → A: 2 経路を提供する。(a) 詳細画面は拡大モーダル内のボタンで即時削除（確認あり）、(b) 編集画面は各写真の ✕ で「削除予定」をマークし、保存ボタン押下時にまとめて削除する
- Q: 新規作成フォームでの写真選択 → A: 保存前に選択中の写真をサムネイルでプレビュー表示する

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ログに写真を添付して見返す (Priority: P1)

ダイバーとして、自分のダイブログに撮影した写真を添付でき、ログ詳細を開いたときに写真付きでその 1 本を振り返れる。ログ作成時にも、後から既存ログを編集して追加することもできる。

**Why this priority**: 本 feature の中核価値。「テキストの記録」が「写真で蘇る思い出」になることでログ蓄積の体感価値が最も上がる。このストーリー単体（自分のログに添付して自分で見る）で MVP として成立する。

**Independent Test**: 認証済みユーザーが任意のダイブログに 1 枚以上の写真を添付し、ログ詳細画面でその写真が表示されることを確認する。公開機能・整理機能とは独立にテスト可能。

**Acceptance Scenarios**:

1. **Given** 認証済みユーザーが自分のダイブログ詳細を開いている, **When** 写真を 1 枚以上選んで添付する, **Then** その写真がログに保存され詳細画面に表示される
2. **Given** ダイブログを新規作成中のユーザー, **When** ログ内容とあわせて写真を選んで保存する, **Then** ログと写真が同時に保存される
3. **Given** すでに写真が添付されたログを持つユーザー, **When** ログ詳細を再度開く, **Then** 添付済みの写真がすべて表示される
4. **Given** 他人のログ, **When** その写真を編集・削除しようとする, **Then** 操作できない（本人のログの写真のみ管理できる）
5. **Given** 未認証のユーザー, **When** 写真添付の操作 URL を開く, **Then** ログイン画面にリダイレクトされる

---

### User Story 2 - 公開ログで写真を共有する (Priority: P2)

ダイバーとして、公開設定にしたログの写真が公開ページ（`public_slug` の URL）にも表示され、ログインしていない友人や他のダイバーにも「潜った海の写真」を見てもらえる。

**Why this priority**: 既存の公開機能との相乗効果で本 feature の価値を増幅する。ただし写真添付（US1）が前提となり、公開機能自体に依存するため US1 の次。

**Independent Test**: 写真付きログを公開設定にし、未認証の状態で公開ページ URL を開いて写真が表示されること、非公開ログの写真は公開ページに出ないことを確認する。

**Acceptance Scenarios**:

1. **Given** 写真を添付したログを公開（is_public = true）にしているユーザー, **When** 未認証の訪問者がその公開ページ URL を開く, **Then** ログ内容とともに写真が表示される
2. **Given** 写真を添付したが非公開のログ, **When** 第三者がそのログにアクセスしようとする, **Then** 写真は一切表示されない（公開ページ自体が存在しない）
3. **Given** 公開中の写真付きログ, **When** 所有者がログを非公開に切り替える, **Then** 以降その写真は公開ページから参照できなくなる
4. **Given** 位置情報（撮影地の GPS）を含む写真, **When** その写真が公開ページに表示される, **Then** 写真から撮影位置などの埋め込みメタ情報は第三者に渡らない

---

### User Story 3 - 写真を整理する (Priority: P3)

> **注**: 並び替え・代表写真指定・キャプション編集（FR-010〜012）は**未実装**（tasks T031〜T034 未着手）。v1 スコープ外として保留中。
> ただし**表示側**（代表写真のサムネイル利用）は feat/design-change で TOP「最近のダイブログ」カードに先行実装済み: `is_cover` フラグの写真を優先し、なければ表示順先頭の写真、写真が 1 枚もないログはロゴのダミー画像を表示する（`getCoverThumbUrls` / `selectCoverThumbPaths`）。

ダイバーとして、1 本のログに複数枚添付した写真の表示順を並び替えたり、代表写真（サムネイル）を指定したり、各写真に短い説明（キャプション）を付けたり、不要な写真を削除したりできる。

**Why this priority**: 添付・閲覧（US1）が成立すれば実用上は足りるが、複数枚を扱うユーザーの満足度を高める。利用頻度は添付そのものより低い。

**Independent Test**: 複数枚の写真を持つログで、並び替え・代表写真指定・キャプション編集・削除を行い、結果が詳細画面（および公開時は公開ページ）に反映されることを確認する。

**Acceptance Scenarios**:

1. **Given** 複数枚の写真を持つログ, **When** 写真の表示順を変更する, **Then** 指定した順で詳細・一覧・公開ページに表示される
2. **Given** 複数枚の写真を持つログ, **When** 1 枚を代表写真に指定する, **Then** ログ一覧やカードのサムネイルにその写真が使われる
3. **Given** 写真にキャプションを付けたログ, **When** その写真を表示する, **Then** キャプションが写真に添えて表示される
4. **Given** 写真を添付したログ, **When** 1 枚を削除する, **Then** その写真だけが取り除かれ、他の写真とログ本体は残る

---

### Edge Cases

- 対応外の形式（動画・極端に大きい画像・破損ファイル）をアップロードしようとした場合、エラー理由を提示して受け付けない
- 1 ログあたりの添付上限・1 ファイルの容量上限を超えた場合、上限を明示して受け付けない
- アップロード中に通信が中断した場合、ログ本体や既存の写真が壊れず、失敗した写真だけが未保存になる
- ログを削除した場合、そのログに紐づく写真もすべて削除される（孤立した写真が残らない）
- 縦・横の向き情報（撮影時の回転）を持つ写真が、意図した向きで表示される
- 代表写真に指定していた写真を削除した場合、代表写真の扱いが破綻しない（自動で別の写真にフォールバック、または未指定に戻る）
- 同じログを複数タブ／端末で同時編集した際に、写真の追加・削除が矛盾なく反映される
- 公開ページで写真の読み込みに失敗した場合でも、ログのテキスト情報は表示される

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは認証済みユーザーが自分のダイブログに 1 枚以上の写真を添付できるようにしなければならない（ログ新規作成時・既存ログの編集時の両方）
- **FR-002**: システムはログ詳細画面で、そのログに添付された写真をサムネイル一覧で表示し、サムネイルをクリックするとモーダル（拡大表示）で大きく閲覧できるようにしなければならない
- **FR-003**: システムは 1 ログあたり最大 10 枚、1 ファイル（変換前の入力ファイル）あたり最大 10MB を上限とし、上限を超える操作は上限値を明示して拒否しなければならない
- **FR-004**: システムは一般的な静止画形式（JPEG / PNG / WebP / HEIC 相当）のみ受け付け、動画・対応外の形式・破損ファイルは理由を提示して拒否しなければならない
- **FR-017**: システムはブラウザでそのまま表示できない形式（HEIC 等）の写真を、保存時に表示可能形式（JPEG / WebP）へ変換しなければならない
- **FR-005**: システムは写真の管理（添付・削除・並び替え・キャプション編集・代表写真指定）を、そのログの所有者本人のみに許可しなければならない
- **FR-006**: システムは公開設定（is_public = true）のログについて、添付写真を公開ページ（public_slug の URL）で未認証の訪問者にも表示しなければならない
  > **注**: 匿名共有ページ（public_slug の未認証閲覧）は 021 で廃止。公開閲覧は認証ユーザー向け `/dives/[id]` に統合された（`20260701130000_drop_get_public_dive_fn.sql`）
- **FR-007**: システムは非公開ログの写真を、所有者以外が一切参照できないようにしなければならない
- **FR-008**: システムはログの公開／非公開の切り替えに、添付写真の参照可否を連動させなければならない（非公開化した時点で公開ページから参照不可）
- **FR-009**: システムは写真のアップロード（変換）時に撮影位置（GPS）などの位置メタ情報を除去して保存し、公開・非公開を問わず位置情報が保持・配信されないようにしなければならない（撮影時の向き情報は FR-016 のため保持する）
- **FR-010**: ユーザーは 1 ログに複数枚添付した写真の表示順を変更でき、指定した順序が表示に反映されなければならない
- **FR-011**: ユーザーは添付写真の 1 枚を代表写真（サムネイル）として指定でき、ログ一覧・カードのサムネイルに使用されなければならない
- **FR-012**: ユーザーは各写真に任意の短い説明（キャプション）を付与でき、写真とともに表示されなければならない
- **FR-013**: ユーザーは添付写真を個別に削除でき、削除は対象の写真のみに限定されなければならない（他の写真・ログ本体は影響を受けない）。削除 UI は 2 経路を提供する: (a) 詳細画面の拡大モーダル内で即時削除（確認あり）、(b) 編集画面で各写真の ✕ により「削除予定」をマークし、保存時にまとめて削除する
- **FR-014**: システムはログを削除した際、そのログに紐づくすべての写真を削除しなければならない（孤立した写真を残さない）
- **FR-015**: システムはアップロード中の中断・失敗時に、ログ本体や既存の写真を破損させず、失敗した写真のみ未保存として扱わなければならない
- **FR-016**: システムは写真の撮影時向き（回転）情報を考慮し、意図した向きで表示しなければならない
- **FR-018**: システムは新規作成フォームで選択した写真を、保存前にサムネイルでプレビュー表示しなければならない

### Key Entities *(include if feature involves data)*

- **写真（Photo）**: ダイブログに添付される 1 枚の静止画。ダイブログに対して N:1 で属する。属性: 画像データへの参照、任意のキャプション、表示順、代表写真フラグ、添付日時。所有者はひも付くダイブログの所有者と一致する
- **ダイブログ（既存）**: 写真の添付先。1 つのログに 0 枚以上の写真がひも付く（1:N）。公開フラグ（is_public）・公開 slug（public_slug）を持ち、写真の公開可否はこのログの公開状態に従う

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーはログ詳細から写真添付の操作を開始してから 3 ステップ以内・1 分以内に 1 枚目の写真を添付できる
- **SC-002**: 一般的なスマートフォン写真（約 5MB）の添付が、標準的な通信環境で 10 秒以内に完了する
- **SC-003**: 公開設定の写真付きログは、未認証の訪問者が公開 URL を開いて追加操作なしに写真を閲覧できる
  > **注**: 匿名共有ページは 021 で廃止。公開閲覧は認証ユーザー向け `/dives/[id]` に統合された（`20260701130000`）ため、本 SC の「未認証の訪問者」前提は認証ユーザーに読み替える
- **SC-004**: 非公開ログの写真が第三者に表示される事象が 0 件である（公開状態に連動して参照可否が切り替わる）
- **SC-005**: 保存・公開いずれの写真からも、撮影位置などの個人を特定し得る位置メタ情報が取得できる事象が 0 件である（アップロード時に常時除去）
- **SC-006**: 写真付きログの一覧表示が、写真なしのログ一覧と比べて体感的な遅延なく（通常データ量で 2 秒以内に）表示される

## Assumptions

- 写真の添付対象は当面ダイブログのみとする（資格証・機材など他エンティティへの添付は本 feature のスコープ外）
- 添付枚数・容量の上限は 1 ログ最大 10 枚 / 1 ファイル最大 10MB に確定。容量上限は変換前の入力ファイルに対して適用する
- 受け付ける形式は一般的な静止画（JPEG / PNG / WebP / HEIC 相当）とし、動画は対象外。HEIC など非表示形式は保存時に表示可能形式（JPEG / WebP）へ変換する
- 写真の公開可否はひも付くログの公開状態を継承する（写真単位の個別公開設定は設けない）
- 認証・ファイル保存・アクセス制御は既存のインフラ基盤（認証基盤・ファイルストレージ・行レベルアクセス制御）を再利用し、本人のみが自分の写真を管理でき、公開写真のみ未認証者が参照できる仕組みとする
- 公開機能（`is_public` / `public_slug`）は本 feature の前提であり、未提供の場合は US1（自分のログへの添付・閲覧）のみで MVP として成立する
- 撮影位置（GPS）はアップロード（変換）時に常時除去するため、公開・非公開・所有者本人を問わず写真からは参照できない（撮影地はダイブログ自体が別途ポイント名等で保持する）
- 想定データ量は既存ログ規模に準じ、ユーザー 1 人あたり数百〜数千枚程度を上限の目安とする
