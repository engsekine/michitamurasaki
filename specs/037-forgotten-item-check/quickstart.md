# Quickstart: 忘れ物確認機能の検証

**Date**: 2026-08-07 | **Plan**: [plan.md](./plan.md)

実装後に機能が end-to-end で動くことを確認する手順。データ仕様は [data-model.md](./data-model.md)、アクション仕様は [contracts/server-actions.md](./contracts/server-actions.md) を参照。

## 前提

```bash
make supabase-reset      # マイグレーション + seed（テストユーザー作成）
make front-up            # service-front を Docker で起動（https://localhost:3000）
```

seed のテストユーザーでログインしておく。

## シナリオ 1: 完了 → 忘れ物確認リスト表示（US1 / FR-001〜003）

1. `/plans/new` で明日以降の日付の予定を作成する（デフォルト持ち物が展開される）
2. 予定詳細の持ち物リストでいくつかチェックを付け、「準備完了」ボタンを押す
3. **期待**: 持ち物リストが忘れ物確認リストに置き換わり、全項目が未確認（0 / N）で表示される
4. ページを再読み込みする → **期待**: 完了状態・忘れ物確認リストが保持されている（FR-004）
5. TOP（`/`）の予定カードを見る → **期待**: 同じ予定が忘れ物確認リスト表示になっている

## シナリオ 2: 最終チェックと「忘れ物なし」（US2 / FR-006）

1. 忘れ物確認リストの項目を確認済みにしていく
2. **期待**: 確認状態が保存され、再読み込み後も保持される
3. 全項目を確認済みにする → **期待**:「忘れ物なし」であることが一目で分かる表示になる

## シナリオ 3: 解除とリセット（US3 / FR-005）

1. 完了中の予定で「完了を解除」する
2. **期待**: 通常の持ち物リストに戻り、準備チェック（1 周目）の状態は完了前のまま
3. 持ち物を 1 件追加し、再度「準備完了」する
4. **期待**: 忘れ物確認リストが全項目未確認から始まり、追加した項目も含まれる（Q1 / FR-008）

## シナリオ 4: ガード（FR-007 / FR-009）

1. 持ち物を全件削除した予定を開く → **期待**: 完了ボタンが表示されない
2. 予定日が昨日以前の予定（終了済み）を開く → **期待**: 完了ボタン・忘れ物確認の操作が表示されない。完了済みだった場合も操作はできない

## 自動テスト

```bash
make front-test                                  # Vitest 単体（actions ガード・コンポーネント）
npx vitest run src/features/plans --root service-front   # plans feature のみ
make front-test-e2e                              # E2E（シナリオ 1〜3 相当）
supabase db lint                                 # マイグレーション lint
```

**期待**: すべて green。カバレッジ閾値（70%）を維持。
