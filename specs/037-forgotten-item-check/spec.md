# Feature Specification: 忘れ物確認機能

**Feature Branch**: `037-forgotten-item-check`

**Created**: 2026-08-07

**Status**: Draft

**Input**: User description: "忘れ物確認機能を作成したい　持ち物リストの完了ボタンを追加して完了したら忘れ物確認リストを表示するようにしたい"

## Clarifications

### Session 2026-08-07

- Q: 完了解除 → 再完了時に忘れ物確認のチェック状態はどうするか → A: リセットして全項目を未確認から確認し直す
- Q: 完了後の持ち物リスト（準備チェック）の表示はどうするか → A: 置き換え表示（完了後は忘れ物確認リストのみ表示し、準備チェックは完了解除で戻る）
- Q: 終了済み（予定日が過去）の予定での扱いはどうするか → A: 完了ボタン・忘れ物確認リストの操作を提供しない（完了状態・確認状態は記録として保持）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 持ち物準備を「完了」して忘れ物確認リストを受け取る (Priority: P1)

ダイバーとして、予定の持ち物リストの準備を終えたら「完了」を宣言したい。完了すると忘れ物確認リストが表示され、出発前に見落としがないかを最終確認できる。

**Why this priority**: 本 feature の中核。完了操作と忘れ物確認リストの表示がなければ機能が成立しない。

**Independent Test**: 持ち物リストを持つ予定で完了操作を行い、忘れ物確認リストが表示されることを確認できれば単独で価値が検証できる。

**Acceptance Scenarios**:

1. **Given** 持ち物リストのある予定、**When** 持ち物リストの「完了」操作を行ったとき、**Then** システムは持ち物リストを完了状態にし、忘れ物確認リストを表示する
2. **Given** 完了済みの持ち物リスト、**When** 予定を再度開いたとき、**Then** システムは完了状態を保持しており、忘れ物確認リストを引き続き表示する
3. **Given** 持ち物が 0 件の予定、**When** 持ち物リストを見たとき、**Then** システムは完了操作を提供しない（確認する対象がないため）

---

### User Story 2 - 忘れ物確認リストで出発前の最終チェックをする (Priority: P2)

ダイバーとして、出発直前に忘れ物確認リストを使って「本当に持ったか」をもう一度確かめたい。準備時のチェックとは別の観点（バッグに入れたか）で確認することで、忘れ物を防ぎたい。

**Why this priority**: 完了操作（US1)の先にある本来の目的（忘れ物の防止）を実現するストーリー。US1 が成立していれば独立して追加できる。

**Independent Test**: 完了済みの持ち物リストで忘れ物確認リストの項目を確認操作し、確認状態が保存されることを単独でテストできる。

**Acceptance Scenarios**:

1. **Given** 忘れ物確認リストが表示されている、**When** 項目を確認済みにしたとき、**Then** システムは確認状態を保存し、再訪問時も保持する
2. **Given** 忘れ物確認リストの全項目が確認済み、**When** リストを見たとき、**Then** システムは「忘れ物なし」であることが一目で分かる表示を行う
3. **Given** 未確認の項目が残っている、**When** リストを見たとき、**Then** システムは未確認の項目数と項目を明確に識別できる形で表示する

---

### User Story 3 - 完了を解除して準備をやり直す (Priority: P3)

ダイバーとして、完了を押した後に持ち物の追加や準備のやり直しが必要になったら、完了を解除して通常の持ち物リストに戻りたい。

**Why this priority**: 誤操作や準備のやり直しへの救済。なくても主要フローは成立するが、実用上は必要。

**Independent Test**: 完了済みの持ち物リストで解除操作を行い、通常の持ち物リスト表示に戻ることを単独でテストできる。

**Acceptance Scenarios**:

1. **Given** 完了済みの持ち物リスト、**When** 完了を解除したとき、**Then** システムは通常の持ち物リスト表示に戻し、準備チェックの状態は完了前のまま保持する
2. **Given** 完了を解除して持ち物を編集した、**When** 再度完了したとき、**Then** システムは最新の持ち物を対象とした忘れ物確認リストを、全項目未確認の状態から表示する（前回の確認状態は引き継がない）

---

### Edge Cases

- 持ち物が 0 件の予定で完了操作はどうなるか？ → 完了操作を提供しない（US1 シナリオ 3）
- 完了後に持ち物リスト側で項目を追加・削除した場合 → 忘れ物確認リストへ最新の項目構成を反映する（FR-008）
- 予定日が過ぎた（終了済みの）予定 → 完了ボタン・忘れ物確認リストの操作を提供しない。完了状態・確認状態は記録として保持する（FR-009）
- 複数の予定がある場合 → 完了状態・確認状態は予定ごとに独立する（FR-004・Assumptions）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、予定の持ち物リストに対して「完了」操作を提供しなければならない
- **FR-002**: システムは、準備チェックの状態にかかわらず完了操作を実行可能にしなければならない（未チェックの持ち物が残っていても完了できる。未チェック分は忘れ物確認リスト側で拾う）
- **FR-003**: システムは、完了操作の実行後に忘れ物確認リストを表示しなければならない。忘れ物確認リストは全持ち物項目を未確認状態から確認し直す「2 周目チェック」方式とし、準備時のチェック状態とは独立した確認状態を持つ。完了中は持ち物リスト（準備チェック）の代わりに忘れ物確認リストのみを表示し、準備チェックへは完了解除（FR-005）で戻る
- **FR-004**: システムは、完了状態を予定ごとに保存し、再訪問時・別画面から開いた場合も保持しなければならない
- **FR-005**: ユーザーは、完了を解除して通常の持ち物リスト表示に戻せなければならない。解除しても準備チェックの状態は失われない。ただし忘れ物確認の確認状態は解除時に破棄し、再完了時は全項目未確認から始める
- **FR-006**: システムは、忘れ物確認リスト上の確認状態を項目ごとに保存し、再訪問時も保持しなければならない
- **FR-007**: システムは、持ち物が 0 件の予定では完了操作を提供してはならない
- **FR-008**: システムは、完了後に持ち物リストの項目が追加・削除された場合、忘れ物確認リストへ最新の項目構成を反映しなければならない
- **FR-009**: システムは、予定日が過去（終了済み）の予定では完了操作・忘れ物確認リストの操作を提供してはならない。既存の完了状態・確認状態は記録として保持する

### Key Entities

- **準備完了状態**: 予定（ダイビング予定）単位の状態。持ち物準備が完了宣言されたかどうかと、その日時を表す
- **忘れ物確認チェック**: 持ち物項目単位の確認状態。準備時のチェック（既存の持ち物チェック）とは独立した「最終確認」の記録

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは持ち物リストから 1 回の操作で忘れ物確認リストに到達できる
- **SC-002**: 完了状態・忘れ物確認の状態は、画面を離れて再訪問しても 100% 保持されている
- **SC-003**: ユーザーは忘れ物確認リストを開いてから 5 秒以内に、未確認（忘れ物の可能性がある）項目を識別できる
- **SC-004**: 持ち物準備の一連のフロー（チェック → 完了 → 忘れ物確認）を 2 分以内に完遂できる

## Assumptions

- 対象は既存のダイビング予定の持ち物リスト（[004-top-dive-plans](../004-top-dive-plans/spec.md) で定義）で、持ち物リスト自体の仕様（デフォルト項目・追加・削除・チェック）は変更しない
- 完了操作と忘れ物確認リストは、持ち物リストが表示される場所（予定詳細、TOP の次の予定 / 当日カード）で利用できる
- 完了状態・確認状態は予定ごとに独立し、ユーザー本人のみが閲覧・操作できる
- リマインド通知（025）との連携（例: 前日に「忘れ物確認をしましょう」）は本 feature の対象外とする
- モバイルアプリ（029）への展開は本 feature の対象外とし、Web（service-front）のみを対象とする
- 忘れ物確認リストは全項目の 2 周目チェック方式（2026-08-07 ユーザー確認済み）。完了操作は未チェックが残っていても実行できる（同確認済み）
