# Feature Specification: デイリーボーナス獲得モーダル

**Feature Branch**: `036-daily-bonus-modal`

**Created**: 2026-07-17

**Status**: Draft

**Input**: User description: "デイリーボーナスを獲得したらモーダルで表示するを実装　別PRで作成して"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - デイリーボーナスの獲得をモーダルで知る (Priority: P1)

ユーザーがその日（JST）はじめてアプリを訪問すると、デイリーボーナスとしてログ枠が 1 つ自動付与される（026 の既存挙動）。現在この付与はサイレントで、ユーザーは獲得に気づけない。本機能では、付与が発生したそのタイミングでモーダルが表示され、「デイリーボーナスを獲得した（+1 枠）」ことと付与後の残枠数が分かる。モーダルは閉じることができ、同じ日に再び表示されることはない。

**Why this priority**: この機能の主目的。デイリーボーナスは無料ユーザーの継続利用インセンティブ（026 US1）だが、付与に気づけなければインセンティブとして機能しない。獲得の可視化は毎日の訪問動機に直結する。

**Independent Test**: 当日未獲得のユーザーでログインし、モーダルが 1 回表示されること・残枠数が正しいこと・閉じられること・リロードや再訪問で再表示されないことを確認できれば単体でテスト可能。

**Acceptance Scenarios**:

1. **Given** 当日分のデイリーボーナスを未獲得のユーザー, **When** その日はじめてログイン済みのページを開く, **Then** 「デイリーボーナス獲得（ログ枠 +1）」と付与後の残枠数を示すモーダルが表示される
2. **Given** ボーナス獲得モーダルが表示されている, **When** 閉じる操作（閉じるボタン・Esc キー・モーダル外クリック）をする, **Then** モーダルが閉じ、元のページをそのまま操作できる
3. **Given** 当日分をすでに獲得済みのユーザー, **When** 同じ日に再度ページを開く（リロード・別ページへの遷移を含む）, **Then** モーダルは表示されない
4. **Given** 日をまたいで（JST）再訪問したユーザー, **When** 新しい日にはじめてページを開く, **Then** その日の分のモーダルが再び表示される

---

### User Story 2 - モーダルからログ作成へ進む (Priority: P2)

獲得モーダルには「さっそくログを書く」導線があり、獲得した枠をそのままログ作成に使える。閉じてそのまま元のページに留まることもできる。

**Why this priority**: ボーナス獲得は「今日もログを書こう」という行動のきっかけ。獲得の通知から作成までを 1 タップでつなぐことで、獲得体験が実利用に変換される。あくまで補助導線のため P2。

**Independent Test**: モーダルの「ログを書く」ボタンでログ作成ページに遷移すること、閉じるだけの選択もできることを確認できれば単体でテスト可能。

**Acceptance Scenarios**:

1. **Given** ボーナス獲得モーダルが表示されている, **When** 「ログを書く」ボタンを押す, **Then** ログ作成ページ（`/dives/new`）へ遷移しモーダルは閉じる
2. **Given** ボーナス獲得モーダルが表示されている, **When** 閉じる操作のみ行う, **Then** ページ遷移は発生せず元のページに留まる

---

### Edge Cases

- ボーナスの付与処理が失敗した訪問では、モーダルを表示しない（既存仕様どおり画面表示も妨げず、次回訪問時の付与で回復する）
- 複数タブ・並行リクエストで同時にページを開いた場合も付与は 1 回のみ（026 の冪等性）であり、モーダルの表示もその付与に対応する 1 回に留まる
- モーダル表示中にページを離れた（遷移した）場合、同日中に再表示はしない（獲得済みであることに変わりはないため）
- スクリーンリーダー利用時もモーダルの出現が伝わり、キーボードのみで閉じる・「ログを書く」の操作が完結する
- 表示の演出（アニメーション）はユーザーの「動きを減らす」設定（prefers-reduced-motion）を尊重する

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはデイリーボーナスの付与が実際に発生した訪問でのみ、獲得モーダルを表示しなければならない（付与が発生しなかった訪問・リロードでは表示してはならない）
- **FR-002**: モーダルには「デイリーボーナスを獲得した」旨・獲得枠数（+1）・付与後のログ枠残数を表示しなければならない
- **FR-003**: モーダルは閉じるボタン・Esc キー・モーダル外の操作で閉じることができ、閉じた後は同日（JST）中に再表示してはならない
- **FR-004**: モーダルにはログ作成ページへの導線を設け、選択時はログ作成ページへ遷移しなければならない
- **FR-005**: ボーナス付与処理が失敗した場合、モーダルは表示せず、ページの表示・操作を一切妨げてはならない（既存のサイレントな失敗許容を維持）
- **FR-006**: モーダルはダイアログとして支援技術に通知され、表示中のフォーカス管理・キーボード操作を含め WCAG 2.1 AA を満たさなければならない
- **FR-007**: 本機能はデイリーボーナスの付与ルール（1 日 1 枠・JST 暦日判定・冪等性。026 FR-003）を一切変更してはならない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 当日はじめての訪問でボーナスが付与されたとき、モーダルが必ず 1 回だけ表示される（表示漏れ・重複表示 0 件)
- **SC-002**: 同日 2 回目以降の訪問・リロード・ページ遷移でモーダルが誤表示される事故が 0 件
- **SC-003**: モーダルの出現から「閉じる」または「ログを書く」までがキーボードのみで完結し、アクセシビリティ自動チェック（WCAG 2.1 AA）で違反 0 件
- **SC-004**: モーダル導入後も、付与失敗を含むすべてのケースでページ本体の表示・操作が妨げられない（画面表示のブロッキング 0 件）

## Assumptions

- デイリーボーナスの付与タイミング・量・判定（ログイン済み領域への当日初アクセス時に 1 枠、JST 暦日、冪等）は 026 の既存仕様のまま変更しない。本機能は「付与の可視化」のみを追加する
- 付与は認証必須ページ群（ログ・予定・プロフィール等）へのアクセスで発生する（026 の既存挙動。TOP `/` はログイン前提ではないページのため付与のトリガーにならない）。モーダルは特定ページに限定せず、付与が発生したページ上に表示する
- アプリ内通知センター（025）への通知追加はスコープ外（モーダルによる即時通知のみ）
- 獲得履歴の一覧表示・過去分の遡り表示はスコープ外
- 演出は控えめとし、獲得済みの事実の伝達を優先する
