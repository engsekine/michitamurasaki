# Feature Specification: 新規登録時の利用規約同意

**Feature Branch**: `018-terms-agreement`

**Created**: 2026-06-26

**Status**: Draft

**Input**: User description: "利用規約同意ボタン追加する　新規登録時にチェックをしないと登録できないようにしたい"

## Clarifications

### Session 2026-06-26

- Q: 利用規約同意チェックはどの新規登録経路に必要か? → A: メール登録（`/signup`）と Google 初回ログイン（`/profile-completion`）の両方で必須
- Q: 同意の記録（監査）はどうするか? → A: 同意日時と同意した規約バージョンを保存し監査可能にする（DB に記録）

### Session 2026-06-27

- Q: 利用規約の提示方法は? → A: モーダル（ダイアログ）で全文を表示し、**最後までスクロールするまで同意チェックを無効化**する（未読同意を防ぐ）。別ページ遷移ではなくモーダル内表示とする

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 利用規約に同意しないと新規登録できない (Priority: P1)

新規ユーザーとして、アカウントを作成する前に利用規約に同意するチェックを行い、同意した場合のみ登録を完了したい（同意しなければ登録できない）。

**Why this priority**: 規約同意の取得は登録フローの必須要件であり、未同意での登録を防ぐことが本機能の核。これが無いと機能が成立しない。

**Independent Test**: `/signup` で、同意チェックを外したまま登録ボタンを押すと登録できず（同意を促すエラー）、チェックを入れると登録できることを確認すれば単独で検証できる。

**Acceptance Scenarios**:

1. **Given** 新規ユーザーが `/signup` を開いている、**When** 利用規約同意チェックを入れずに「新規登録」を実行しようとする、**Then** システムは登録を実行せず、利用規約への同意が必要である旨のエラーを表示する
2. **Given** 新規ユーザーが他の必須項目を正しく入力済みである、**When** 利用規約同意チェックを入れて「新規登録」を実行する、**Then** システムは登録処理を実行する
3. **Given** 利用規約同意チェックを一度入れた後に外した、**When** 「新規登録」を実行しようとする、**Then** システムは登録を実行せず同意を促す
4. **Given** `/signup` のフォーム、**When**「利用規約を読む」を押す、**Then** システムはモーダルで利用規約の全文を表示する（入力中の内容は失われない）
5. **Given** 利用規約モーダルが開いている、**When** 最後までスクロールしていない、**Then** 同意チェックは無効（チェックできない）
6. **Given** 利用規約モーダルを最後までスクロールした、**When** モーダルを閉じる、**Then** 同意チェックが有効になり、チェックできる

---

### User Story 2 - Google など他経路の新規登録でも同意を必須にする (Priority: P2)

Google アカウントで初めてログインして新規にアカウントを作るユーザーとして、メール登録と同様に利用規約への同意を求められ、同意しないと利用を開始できないようにしたい。

**Why this priority**: 新規登録の入口はメール＋パスワードだけでなく Google 初回ログイン（プロフィール補完）も含む。同意を片方だけにすると規約取得に抜けが生じる。ただしメール経路（US1）が先に成立すれば価値は出るため P2。

**Independent Test**: 未登録の Google アカウントで初回ログイン → プロフィール補完画面で同意チェックを外したまま送信すると進めず、チェックを入れると TOP（`/`）に到達できることを確認すれば単独で検証できる。

**Acceptance Scenarios**:

1. **Given** Google 初回ログインのプロフィール補完画面、**When** 利用規約同意チェックを入れずに送信する、**Then** システムは登録（補完）を完了せず同意を促す
2. **Given** Google 初回ログインのプロフィール補完画面、**When** 同意チェックを入れて送信する、**Then** システムは補完を完了し利用を開始させる

---

### Edge Cases

- 同意チェックを入れてから外した場合 → 登録は実行されず、同意を促すエラーになる
- キーボードのみ / スクリーンリーダー利用時も、規約モーダルの開閉・スクロール・同意チェックの状態変更・エラーの認識ができること
- 規約モーダルを開いてもフォームの入力内容が保持されること（同一画面のモーダル表示）
- 利用規約がスクロール不要な短さの場合は「最後まで読んだ」とみなし、同意チェックを有効にすること（永久に同意不可になるのを防ぐ）
- 既存ユーザーのログイン（`/login`）には同意チェックを要求しない（新規登録時のみ）
- サインアップ要求がサーバー側で受理される直前にも、同意なしの登録を受け付けないこと（クライアントの無効化だけに依存しない）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは `/signup`（新規登録フォーム）に利用規約への同意チェックを表示しなければならない
- **FR-002**: システムは同意チェックが未チェックの状態では新規登録を実行してはならない
- **FR-003**: システムは同意チェックが入っている場合のみ新規登録を実行しなければならない
- **FR-004**: システムは未チェックで登録が試みられたとき、利用規約への同意が必要である旨のエラーメッセージを表示しなければならない
- **FR-005**: システムは「利用規約を読む」導線から利用規約の全文を**モーダル（ダイアログ）**で表示し、表示中もフォームの入力内容を失わせてはならない（別ページ遷移にしない）
- **FR-005b**: システムは利用規約モーダルを**最後までスクロールするまで同意チェックを無効**にし、最後まで到達した後にのみ同意チェックを可能にしなければならない（スクロール不要な短さの場合は到達済みとして扱う）
- **FR-006**: システムは同意チェック・モーダル・エラー表示をアクセシブルにしなければならない（チェックボックスとラベルの関連付け、エラーの `role="alert"` と `aria-invalid`、モーダルのフォーカストラップ・Esc・`aria-modal`、キーボード操作）
- **FR-007**: システムは既存ユーザーのログイン（`/login`）には利用規約同意を要求してはならない（新規登録時のみ）
- **FR-008**: システムはクライアント側の無効化だけに依存せず、新規登録の確定処理側でも未同意の登録を拒否しなければならない
- **FR-009**: システムはメール登録（`/signup`）と Google 初回ログイン（`/profile-completion`）の**両方**で利用規約同意を必須にしなければならない（いずれの経路でも未同意では新規登録／利用開始をさせない）
- **FR-010**: システムは利用規約への同意の事実を記録しなければならない。具体的には、同意した日時と同意した規約バージョンを保存し、後から監査できるようにする

### Key Entities *(include if feature involves data)*

- **利用規約同意（terms agreement）**: 新規登録時にユーザーが行う同意。登録の必須条件であり、**同意日時・同意した規約バージョン**を保存して監査可能にする（メール登録・Google 初回ログインの両経路で記録）。1 ユーザーに紐づく（保存先テーブル/カラムは plan で確定）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 同意チェックを入れていない状態では、新規登録が 100% 完了しない（メール登録・Google 初回ログインの両経路）
- **SC-005**: 新規登録が完了したユーザーには、同意日時と規約バージョンが記録されている（監査可能）
- **SC-002**: 同意チェックを入れた場合、追加のサポートなしに新規登録を完了できる
- **SC-003**: 新規登録フローの全受け入れ条件（未チェックで拒否・チェックで登録・規約モーダル表示・スクロール末尾で同意可・入力保持）が E2E テストで再現・合格する
- **SC-004**: 同意チェックとエラー表示が WCAG 2.1 AA を満たす（キーボードで操作可能、ラベル関連付け、エラーが支援技術に伝わる）

## Assumptions

- 利用規約は既存ページ `/terms` を参照する
- 本機能は「新規登録時の同意取得」が対象であり、既存ユーザーへの再同意（規約改定時の再同意フロー）は本フェーズの対象外
- 同意 UI は単一の「利用規約に同意する」チェックとし、規約全文は「利用規約を読む」モーダルで表示する。規約本文は `/terms` ページと同じ内容を共有コンポーネントで再利用する
- 規約モーダルは同一画面内に表示するため、開いてもフォーム入力は保持される
- 認証基盤（既存の `001-auth` / `016-google-login`）の登録処理に同意チェックを組み込む形を取り、新たな登録経路は追加しない
- 以下は本フェーズの対象外:
  - 規約改定時の既存ユーザーへの再同意要求
  - 同意撤回フロー
  - 複数言語の規約
