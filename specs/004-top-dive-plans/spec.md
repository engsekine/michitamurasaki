# Feature Specification: TOP ページ拡張（ダイビング予定 / 持ち物リスト）

**Feature Branch**: `004-top-dive-plans`

**Created**: 2026-06-11

**Status**: Implemented（2026-06-11）

**Input**: User description: "TOPページ作成　累計潜水時間機能　レギュレーターのオーバーホール日機能　ダイビング予定機能　持ち物リスト　を含めたい"

## 概要

ログインしたダイバーが TOP ページで「これまで（累計統計・機材状態）」と「これから（ダイビング予定・持ち物準備）」の両方を一望できるようにする。

要望 5 項目のうち **TOP ページ作成 / 累計潜水時間 / レギュレーター OH 日** は既存の [003-dashboard](../003-dashboard/spec.md)（確定済み・実装未着手）で仕様化済みのため、本 feature は **ダイビング予定機能** と **持ち物リスト** を新規に定義し、TOP ページへの統合部分（「次の予定」セクション追加）を 003 への差分として扱う（2026-06-11 ユーザー確認済み: 003 は確定仕様のまま活かす）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ダイビング予定を登録して管理する (Priority: P1)

ダイバーとして、次に潜りに行く予定（日付・ポイント・メモ）を登録し、一覧で確認・編集・削除したい。

**Why this priority**: 予定が存在しないと TOP 表示も持ち物リストも成立しない、本 feature の中核データ。

**Independent Test**: 予定の作成 → 一覧表示 → 編集 → 削除が単体で確認でき、それだけで「次はいつどこに潜るか」を管理する価値を提供する。

**Acceptance Scenarios**:

1. **Given** 認証済みユーザー、**When** 予定日とポイント名を入力して保存したとき、**Then** システムは予定を保存し予定一覧に表示する
2. **Given** 予定が複数件存在する、**When** 予定一覧を開いたとき、**Then** システムは予定日昇順（直近が先頭）で表示する
3. **Given** 過去日になった予定が存在する、**When** 予定一覧を開いたとき、**Then** システムは過去の予定を「終了済み」として区別して表示する
4. **Given** 自分の予定、**When** 削除を確認ダイアログで承認したとき、**Then** システムは予定を削除する
5. **Given** 必須項目（予定日・ポイント名）が未入力、**When** 保存しようとしたとき、**Then** システムは該当フィールドにエラーを表示する

---

### User Story 2 - TOP で「次の予定」を確認する (Priority: P2)

ダイバーとして、TOP ページを開いたときに次のダイビング予定（日付・ポイント・あと何日か）が目に入るようにしたい。累計潜水時間やレギュレーター OH 状況（003 で定義済み）と並んで表示されることで、TOP が「過去と未来のハブ」になる。

**Why this priority**: 予定管理（US1）が成立していれば、TOP 統合は表示の追加で価値が出る。003 のダッシュボード実装と同時期に進められる。

**Independent Test**: 予定ありユーザーの TOP に「次の予定」カード（日付・ポイント・残り日数）が表示され、予定なしユーザーには登録導線が表示されることで確認できる。

**Acceptance Scenarios**:

1. **Given** 未来の予定が 1 件以上ある、**When** TOP を開いたとき、**Then** システムは FV に最も近い予定 1 件（予定日（曜日付き）・ポイント名・残り日数「あと N 日」）を、本文の「次のダイビング予定」セクションに近い順で最大 3 件の詳細カードを表示する（feat/design-change で拡張）
2. **Given** 予定が 0 件（または全て過去日）、**When** TOP を開いたとき、**Then** システムは「次のダイビングを計画しよう」CTA と予定作成への導線を表示する。「予定を作成する」ボタンは予定の有無にかかわらず FV・セクション見出し行に常時表示する
3. **Given** 次の予定に持ち物リストがある、**When** TOP の予定カードを見たとき、**Then** システムは持ち物の準備進捗（チェック済み / 全件数 + プログレスバー）と全項目のチェックリストを表示し、カード上でチェック状態を直接切り替えられる（feat/design-change で拡張。従来はチェック済み先頭 3 件の抜粋表示）

---

### User Story 3 - 予定ごとの持ち物リストで準備する (Priority: P3)

ダイバーとして、ダイビング予定ごとに持ち物リストを作り、出発前にチェックを付けながら準備したい。毎回ゼロから書かなくて済むよう、定番の持ち物が最初から入っていてほしい。

**Why this priority**: 予定（US1）に従属する付加価値機能。予定単体でも価値はあるが、持ち物チェックが揃うと「準備のためのアプリ」として完成する。

**Independent Test**: 予定詳細で持ち物リストにデフォルト項目が表示され、チェックの付け外し・項目の追加・削除が永続化されることで確認できる。

**Acceptance Scenarios**:

1. **Given** 予定を新規作成した、**When** その予定の持ち物リストを開いたとき、**Then** システムはデフォルトの持ち物項目（ダイビングの定番装備）をチェック未済状態で表示する
2. **Given** 持ち物リストが表示されている、**When** 項目のチェックを付け外ししたとき、**Then** システムは状態を保存し、再訪時も維持する
3. **Given** 持ち物リストが表示されている、**When** カスタム項目（例: 酔い止め）を追加したとき、**Then** システムはその予定のリストに項目を追加する
4. **Given** 不要な項目がある、**When** 項目を削除したとき、**Then** システムはその予定のリストから項目を削除する

> 持ち物リストのモデルは「予定ごとのリスト + 固定のデフォルト項目」方式で確定（2026-06-11 ユーザー確認済み）。ユーザー編集可能なマイテンプレート方式は採用しない。

---

### Edge Cases

- 予定日に今日を指定した場合 → 「あと 0 日（今日）」として未来扱いで表示する
- 予定が同日に複数ある場合 → 並び順は予定日昇順・同日は作成日時が新しい順（FV の 1 件は先頭）。TOP の詳細カードは最大 3 件まで表示するため同日の複数予定も枠内なら両方表示される。一覧では全件表示する
- 持ち物リストの全項目をチェック済みにした場合 → 進捗表示を「準備完了」状態にする
- 予定を削除した場合 → 紐づく持ち物リストも一緒に削除される
- 過去日になった予定の持ち物リスト → 閲覧は可能だが TOP の進捗表示対象にはならない

## Requirements *(mandatory)*

### Functional Requirements

#### ダイビング予定（一覧 / 作成 / 編集 / 削除）

- **FR-001**: システムは、認証済みユーザーが予定一覧を開いたとき、自分の予定を予定日昇順で表示しなければならない。予定が 0 件のときは「次のダイビングを計画しよう」CTA と予定作成への導線を表示する
- **FR-002**: ユーザーは、予定日（必須）・ポイント名（必須）・メモ（任意）を入力して予定を作成できなければならない
- **FR-003**: システムは、必須項目が欠けているとき該当フィールドにエラーメッセージを表示しなければならない
- **FR-004**: ユーザーは、自分の予定を編集・削除できなければならない（削除は確認ダイアログを挟む）
- **FR-005**: システムは、予定日が過去になった予定を「終了済み」として未来の予定と区別して表示しなければならない

#### TOP ページへの統合

- **FR-006**: システムは、TOP ページ（003-dashboard 定義のダッシュボード）に「次の予定」セクションを追加しなければならない。現行 TOP（`/`）は公開ルートのため、未認証ユーザーには本セクションを表示しない（003 で `/` が認証必須化された後はリダイレクトに委ねる）
- **FR-007**: システムは、未来の予定を近い順に表示しなければならない。FV には最も近い 1 件（予定日・ポイント名・残り日数）、本文の「次のダイビング予定」セクションには簡素な一覧（`NextPlanList`: 予定日（曜日付き）— 行き先 / 残り日数バッジ。持ち物の準備は表示しない）を最大 5 件表示する（2026-08-07 に詳細カード最大 3 件 → 一覧最大 5 件に変更）
- **FR-007a**: システムは、予定日が当日（今日）の予定があるとき、FV の見出しを「今日のダイビング予定」に切り替え、簡素な 1 行表示の代わりに詳細カード（持ち物チェックリスト付き・FR-009 と同等）を FV 内に表示しなければならない。当日の予定は本文の「次のダイビング予定」セクションからは除外し、残りの将来の予定のみを表示する
- **FR-008**: システムは、未来の予定が 0 件のとき「次のダイビングを計画しよう」CTA と予定作成導線を表示しなければならない。予定作成導線（「予定を作成する」）は予定の有無にかかわらず常時表示する。ただし FV が当日表示（FR-007a）のときは、カード内の導線（予定の詳細 / 持ち物を準備する）に集中させるため FV の予定作成導線は表示しない（本文セクション見出し行の導線は維持）
- **FR-009**: システムは、次の予定に持ち物リストがあるとき、準備進捗（チェック済み件数 / 全件数）と全項目のチェックリストを表示し、TOP のカード上でチェック状態を切り替えられなければならない（feat/design-change で操作可能に拡張）
- 持ち物リストの「準備完了」と忘れ物確認リスト（2 周目チェック）は [037-forgotten-item-check](../037-forgotten-item-check/spec.md) で拡張された。完了中は持ち物リスト・カード右ペインが忘れ物確認リストに置き換わる

#### 持ち物リスト

- **FR-010**: システムは、予定ごとに持ち物リストを 1 つ持たせなければならない
- **FR-011**: システムは、予定の新規作成時にデフォルトの持ち物項目一式をチェック未済状態でリストに展開しなければならない
- **FR-012**: ユーザーは、項目のチェック状態を切り替えられ、システムはそれを永続化しなければならない
- **FR-013**: ユーザーは、カスタム項目の追加・項目の削除ができなければならない
- **FR-014**: システムは、予定が削除されたとき紐づく持ち物リストも削除しなければならない

#### データアクセス

- **FR-015**: システムは、予定・持ち物データを認証ユーザー本人のものに限定しなければならない
- **FR-016**: システムは、未認証ユーザーが予定関連ページを開いたときログインページへリダイレクトしなければならない

### Key Entities

- **dive_plans（新規）**: ダイビング予定。予定日（必須）/ ポイント名（必須）/ メモ（任意）を持ち、ユーザーに従属する（user 1 : N plans）
- **plan_packing_items（新規）**: 予定ごとの持ち物項目。名称 / チェック状態 / 表示順を持ち、予定に従属する（plan 1 : N items、予定削除で連動削除）
- **dives（既存・参照のみ）**: 累計潜水時間の集計元（定義は 003-dashboard の FR-003 / FR-005）。本 feature ではスキーマ変更なし
- **regulators（003 で新規定義）**: OH ステータス表示の元。本 feature では変更なし

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは予定の登録を 1 分以内に完了できる（必須 2 項目のみで保存可能）
- **SC-002**: TOP を開いて 3 秒以内に「次の予定までの残り日数」と「持ち物の準備進捗」を把握できる
- **SC-003**: 持ち物リストはチェック操作後にページを離れて戻っても 100% 状態が維持される
- **SC-004**: 予定・持ち物データが他ユーザーから参照・操作できないことが確認できる（アクセス制御テストで違反 0 件）
- **SC-005**: デフォルト持ち物項目により、ユーザーが手入力なしでも 10 項目以上のチェックリストを即座に使い始められる

## Assumptions

- 003-dashboard（TOP / 累計統計 / レギュレーター OH）は確定済み仕様として活かし、本 feature は予定・持ち物の追加と TOP への「次の予定」セクション追加のみを扱う
- 予定は個人のものとし、バディとの共有・公開機能は対象外
- リマインダー通知（メール / プッシュ）は対象外（TOP 表示のみで気づける設計）
- 天気・潮汐情報などの外部データ連携は対象外
- デフォルト持ち物項目の内容（例: マスク、フィン、レギュレーター、スーツ、ログブック、Cカード 等）は実装計画時に確定する
- 予定の時刻（集合時間等）は管理せず日付単位とする。詳細はメモ欄で補う

## Out of Scope（本 feature では扱わない）

- 終了済み予定からの「この予定をログにする」導線（予定 → ログ作成フォームへの初期値引き継ぎ。後続 feature 候補）
- ユーザー編集可能な持ち物マイテンプレート（後続 feature 候補）
- 予定のリマインダー通知
- 予定・持ち物リストの共有 / 公開
- ショップ・ツアー予約との連携
- 持ち物リストの予定をまたいだ使い回し履歴・統計
- 累計潜水時間・レギュレーター OH の仕様変更（003-dashboard の定義を変更しない）
