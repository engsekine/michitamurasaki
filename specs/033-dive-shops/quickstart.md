# Quickstart: ダイビングショップ登録（033-dive-shops）

実装完了後に機能が end-to-end で動くことを検証する手順。詳細な契約は [contracts/](contracts/)・[data-model.md](data-model.md) を参照。

## 前提

```bash
# ローカル Supabase + マイグレーション適用
npx supabase start
npx supabase db reset   # seed に test@example.com / password123 が含まれる

# dev サーバー
npm run dev --workspace service-front   # http://localhost:3000
```

- 地図・ジオコーディングを検証する場合は `service-front/.env` に `GOOGLE_MAPS_API_KEY` を設定する。未設定でもシナリオ 1・3〜6 は検証可能（地図は「表示できない」メッセージになる）

## シナリオ 1: ショップの登録・編集・削除（US1）

1. `test@example.com` でログイン → ヘッダーの「ショップ」→ `/shops`
2. 空状態メッセージと登録導線を確認 → 「ショップを登録」
3. 名前だけ入力して保存 → **期待**: 登録成功・詳細に遷移（住所なしのため地図領域は非表示）
4. 名前を空にして保存 → **期待**: `role="alert"` のエラーで登録されない
5. 全項目入力で 2 件目を登録 → **期待**: 一覧に 2 件。詳細で URL が別タブで開く
6. 編集で項目変更 → **期待**: 反映。削除（確認ダイアログ）→ **期待**: 一覧から消える

## シナリオ 2: 住所 → 地図表示（US3・要 API キー）

1. `/shops/new` で住所欄に実在の住所（例: 「静岡県伊東市富戸」）を入力し、欄からフォーカスを外す
2. **期待**: 追加操作なしで該当地点の Google マップ iframe が表示される（FR-011 / SC-003）
3. 住所を架空の文字列（例: 「あいうえお市かきくけこ 9-9-9」）に変えて確定 → **期待**: 地図が消え「地図を表示できない」旨の表示。保存は可能（FR-013）
4. 保存後の詳細画面 → **期待**: 保存済み座標で地図表示（このとき外部 API は呼ばれない）

## シナリオ 3: 予定・ログ・シートへの紐付け（US2）

1. `/plans/new` を開く → ショップ選択欄に登録済みショップが表示される → 選択して保存 → **期待**: 予定詳細にショップ名（`/shops/[id]` へのリンク）
2. `/dives/new` でも同様に選択・保存 → **期待**: ログ詳細にショップ名
3. `/application-sheet` で宛先ショップを選択し「シートを保存する」→ 再訪問して保存済みシートを開く → **期待**: 宛先ショップが復元されている（FR-009）
4. ショップ未選択でも予定・ログ・シートを保存できる（紐付けは任意）
5. ショップ詳細を開く → **期待**: 紐付けた予定・ログが逆引き一覧に表示され、各詳細へたどれる（FR-016）

## シナリオ 4: ショップ削除時の紐付け解除（FR-010 / SC-005）

1. シナリオ 3 のショップを削除する
2. **期待**: 予定・ログ・シート保存内容はすべて残り、ショップ表示だけが消える（詳細画面にショップ欄が出ない / 未選択に戻る）

## シナリオ 5: 非公開の確認（FR-015）

1. ショップを紐付けたログを公開設定にする（既存の公開トグル）
2. 別アカウント（または未ログインの公開リンク）でそのログ・タイムラインを閲覧
3. **期待**: ショップの名前・住所等が一切表示されない（本人で見ると表示される）

## シナリオ 6: 認証ガード・a11y・モバイル

1. 未ログインで `/shops` へアクセス → **期待**: `/login` にリダイレクト
2. 375px 幅で `/shops` `/shops/new` を表示 → **期待**: 横スクロールなし・タッチターゲット 44px 以上
3. axe スキャン（Playwright a11y スイープ）で WCAG 2.1 AA 違反 0 件（地図 iframe の `title` 含む）
