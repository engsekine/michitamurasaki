# Feature Specification: ダイビングショップ登録

**Feature Branch**: `033-dive-shops`

**Created**: 2026-07-11

**Status**: Draft

**Input**: User description: "ユーザーがダイビングショップを登録できるようにしたい　ログの予定とログ、申し込みシートテンプレと紐付けできるようにしたい　項目は、名前、住所、電話番号、webサイトURL、メモ欄　住所を入力するとgooglemapで地図が表示されるようにしたい"

## Clarifications

### Session 2026-07-11

- Q: ショップを紐付けたログが公開（タイムライン・公開リンク）された場合、他ユーザーが見る画面にショップ情報を表示するか？ → A: 表示しない。ショップ情報は本人が閲覧する画面にのみ表示する
- Q: ショップ詳細画面に「このショップに紐付いた予定・ログの一覧」を表示するか？ → A: 表示する。一覧から各予定・ログの詳細へたどれるようにする
- Q: ショップの一覧・登録画面はどこに設置するか？ → A: 予定・ログと同列の独立ページとして設置し、ナビゲーションから直接たどれるようにする（設定配下にはしない）
- Q: 登録・編集画面で地図はどのタイミングで表示・更新するか？ → A: 住所の入力が確定したタイミング（入力欄から離れた時など）で自動的に表示・更新する（明示的なボタン操作は要しない）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ショップを登録・管理する (Priority: P1)

ユーザーは、行きつけ・利用予定のダイビングショップをアプリに登録できる。登録項目は名前（必須）・住所・電話番号・Web サイト URL・メモ欄（いずれも任意）。登録したショップは一覧で確認でき、詳細の閲覧・編集・削除ができる。詳細画面では電話番号や Web サイトへすぐアクセスでき、「送迎あり」「器材レンタルが安い」などの個人的なメモを見返せる。

**Why this priority**: ショップ情報の記録・参照がこの機能の土台。紐付け（US2）も地図表示（US3）も、ショップが登録できて初めて成立する。これ単体でも「ショップの連絡先・メモ帳」として価値が成立する。

**Independent Test**: ショップを 1 件登録し、一覧・詳細に表示されること、編集・削除が反映されることを確認すれば単体でテスト可能。

**Acceptance Scenarios**:

1. **Given** ログイン済みユーザーがショップ登録画面を開いている, **When** 名前を入力して保存する, **Then** ショップが登録され一覧に表示される
2. **Given** ショップ登録画面, **When** 名前・住所・電話番号・Web サイト URL・メモをすべて入力して保存する, **Then** 全項目が保存され詳細画面で確認できる
3. **Given** ショップ登録画面, **When** 名前を空のまま保存する, **Then** エラーメッセージが表示され登録されない
4. **Given** 登録済みショップの詳細画面, **When** 項目を編集して保存する, **Then** 変更内容が反映される
5. **Given** 登録済みショップ, **When** 削除操作を行い確認ダイアログで OK する, **Then** ショップが削除され一覧から消える
6. **Given** Web サイト URL が登録されたショップの詳細画面, **When** URL を選択する, **Then** ショップの Web サイトが別タブで開く
7. **Given** 別のユーザーが登録したショップ, **When** 自分のショップ一覧を開く, **Then** 他ユーザーのショップは表示されない（本人のみ参照・変更できる）

---

### User Story 2 - 予定・ログ・申し込みシートにショップを紐付ける (Priority: P2)

ユーザーは、ダイビング予定の作成・編集時、ダイブログの作成・編集時、申し込みシートの作成時に、登録済みショップの中から 1 件を選択して紐付けられる。予定・ログの詳細にはショップ名が表示され、そこからショップ詳細（連絡先・メモ）へたどれる。「どのショップで潜ったか / 潜るか」「どのショップ宛の申し込みシートか」が記録として残る。

**Why this priority**: 予定・ログ・申し込みシートと結びついて初めて「ショップ台帳」から「ダイビング記録の一部」になる、この機能の主目的。ただしショップ登録（US1）が先に成立している必要がある。

**Independent Test**: ショップ登録済みの状態で予定・ログ・申し込みシートを作成してショップを選択し、それぞれの詳細（シートは保存内容）にショップが紐付いて表示されることを確認すれば単体でテスト可能。

**Acceptance Scenarios**:

1. **Given** ショップ登録済みのユーザーが予定の作成・編集画面を開いている, **When** ショップ選択欄から 1 件選んで保存する, **Then** 予定にショップが紐付き、予定詳細にショップ名が表示される
2. **Given** ショップ登録済みのユーザーがログの作成・編集画面を開いている, **When** ショップを選択して保存する, **Then** ログにショップが紐付き、ログ詳細にショップ名が表示される
3. **Given** 申し込みシート作成画面, **When** ショップを選択する, **Then** シートにショップが紐付き、次回以降どのショップ宛に作成したかが分かる
4. **Given** ショップを 1 件も登録していないユーザー, **When** 予定・ログ・シートを作成する, **Then** ショップ未選択のまま従来どおり保存できる（紐付けは任意）
5. **Given** ショップが紐付いた予定・ログ, **When** 紐付けたショップを削除する, **Then** 予定・ログ自体は残り、ショップの紐付けだけが解除される
6. **Given** ショップが紐付いた予定・ログの編集画面, **When** ショップ選択を解除（未選択に変更）して保存する, **Then** 紐付けが解除される
7. **Given** 予定・ログが紐付いたショップ, **When** ショップ詳細画面を開く, **Then** そのショップに紐付いた予定・ログの一覧が表示され、各詳細へたどれる

---

### User Story 3 - 住所から地図で場所を確認する (Priority: P3)

ユーザーがショップの登録・編集画面で住所を入力すると、その住所の位置が Google マップの地図で表示され、場所が正しいかその場で確認できる。ショップ詳細画面でも住所とあわせて地図が表示され、初めて行くショップの場所を出発前に確認できる。

**Why this priority**: 住所の入力ミス防止と現地確認の利便性を高める付加価値。地図がなくてもショップの登録・紐付け（US1・US2）は成立するため P3 とする。

**Independent Test**: 登録・編集画面で実在の住所を入力して地図が該当地点を表示すること、詳細画面でも同じ地図が表示されることを確認すれば単体でテスト可能。

**Acceptance Scenarios**:

1. **Given** ショップ登録・編集画面, **When** 実在の住所を入力して入力を確定する（入力欄から離れる）, **Then** 追加の操作なしに、その住所の位置を示す Google マップの地図が画面内に表示される
2. **Given** 住所が登録されたショップ, **When** 詳細画面を開く, **Then** 住所の位置を示す地図が表示される
3. **Given** ショップ登録・編集画面, **When** 位置を特定できない住所（架空・不完全な住所）を入力する, **Then** 地図は表示されず「地図を表示できない」旨が分かる表示になり、保存自体は妨げられない
4. **Given** 住所未入力のショップ, **When** 詳細画面を開く, **Then** 地図領域は表示されない（空の地図や誤った位置を表示しない）

---

### Edge Cases

- 位置を特定できない住所（架空・不完全・表記ゆれ）を入力した場合 → 地図は非表示 + その旨の表示。住所の保存は妨げない
- Web サイト URL の形式が不正な場合（例: `htp://` や URL でない文字列）→ エラーメッセージを表示して保存を拒否する
- 紐付け先として選択済みのショップを削除した場合 → 予定・ログ・シートは残り、紐付けのみ解除される
- 同じ名前のショップを複数登録した場合 → 重複登録を許容する（系列店・同名別店舗がありうるため）。選択欄では住所等で区別できる
- 地図の表示に失敗した場合（外部サービスの障害・通信エラー）→ ショップの登録・閲覧機能自体は影響を受けない
- ショップを 1 件も登録していない状態で予定・ログ・シートのショップ選択欄を開いた場合 → 空である旨とショップ登録への導線を表示する
- ショップを紐付けたログを公開（タイムライン・公開リンク）した場合 → 他ユーザーが見る画面にはショップ情報を一切表示しない（本人の画面にのみ表示する）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ユーザーはショップを名前（必須）・住所・電話番号・Web サイト URL・メモ（いずれも任意）の項目で登録できなければならない
- **FR-002**: システムは入力値を検証しなければならない: 名前は 120 文字以内で空白のみ不可、住所は 255 文字以内、電話番号は電話番号として妥当な形式（数字・ハイフン・`+`）、Web サイト URL は URL 形式、メモは 1000 文字以内
- **FR-003**: ユーザーは自分が登録したショップの一覧を確認でき、各ショップの詳細（全項目）を閲覧できなければならない。ショップ一覧は予定・ログと同列の独立ページとして設置し、ナビゲーションから直接たどれること
- **FR-004**: ユーザーは登録済みショップの各項目を編集できなければならない
- **FR-005**: ユーザーは確認ダイアログを経てショップを削除できなければならない
- **FR-006**: ショップは登録した本人のみが参照・編集・削除できなければならない（他ユーザーには一切見えない）
- **FR-007**: ユーザーはダイビング予定の作成・編集時に、登録済みショップから 1 件を任意で選択して紐付けられなければならない。予定詳細には紐付いたショップ名を表示し、ショップ詳細へたどれること
- **FR-008**: ユーザーはダイブログの作成・編集時に、登録済みショップから 1 件を任意で選択して紐付けられなければならない。ログ詳細には紐付いたショップ名を表示し、ショップ詳細へたどれること
- **FR-009**: ユーザーは申し込みシートの作成時に、登録済みショップから 1 件を任意で選択して紐付けられなければならない（どのショップ宛のシートかを記録する）
- **FR-010**: システムはショップが削除されたとき、そのショップに紐付いていた予定・ログ・シートの紐付けを解除し、予定・ログ・シート自体は保持しなければならない
- **FR-011**: システムはショップの登録・編集画面で住所の入力が確定したとき（入力欄から離れた時など）、追加の明示操作なしに、その住所の位置を示す Google マップの地図を自動で表示・更新しなければならない
- **FR-012**: システムは住所が登録されたショップの詳細画面で、住所の位置を示す地図を表示しなければならない
- **FR-013**: システムは住所から位置を特定できない場合、地図を表示せずその旨をユーザーに伝え、ショップの保存・閲覧を妨げてはならない
- **FR-014**: システムはショップ詳細の Web サイト URL を選択したとき、ショップのサイトを別タブで開かなければならない
- **FR-015**: システムはショップ情報（名前を含む一切の項目）を登録した本人が閲覧する画面にのみ表示しなければならない。公開されたログ・タイムラインなど他ユーザーが閲覧する画面にはショップ情報を表示してはならない
- **FR-016**: システムはショップ詳細画面に、そのショップに紐付いた予定・ログの一覧を表示し、各予定・ログの詳細へたどれるようにしなければならない（紐付きが 0 件の場合はその旨を表示する）

### Key Entities

- **ダイビングショップ**: ユーザーが登録する店舗情報。名前（必須）・住所・電話番号・Web サイト URL・メモを持つ。登録したユーザー本人だけのプライベートなデータ
- **ダイビング予定**: 既存機能。ショップを任意で 1 件紐付けられる（紐付けなしも可）
- **ダイブログ**: 既存機能。ショップを任意で 1 件紐付けられる（紐付けなしも可）
- **申し込みシート**: 既存機能（032）。作成時にショップを任意で 1 件紐付けられ、どのショップ宛かを記録する

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーはショップ 1 件の登録（名前 + 住所 + 電話番号）を 2 分以内に完了できる
- **SC-002**: 予定・ログの作成フロー中、登録済みショップの紐付けに追加で必要な操作は選択のみ（3 タップ以内）で完了する
- **SC-003**: 実在する住所を入力したケースの 90% 以上で、該当地点の地図が入力画面内にそのまま表示される（別アプリ・別画面への移動なし）
- **SC-004**: ショップ詳細から電話番号・Web サイトへのアクセスがそれぞれ 1 操作で行える
- **SC-005**: ショップの削除が紐付け先の予定・ログ・シートのデータ消失を引き起こすケースが 0 件である

## Assumptions

- ショップはユーザーごとのプライベートデータとする（マスタ共有・他ユーザーとの共用はしない）。既存の器材・保有資格と同じ位置づけ
- 紐付けは予定・ログ・申し込みシートいずれも「1 件のショップを任意で選択」とする（複数ショップの同時紐付けは対象外）
- 「申し込みシートテンプレとの紐付け」は、申し込みシート機能（032）の作成・保存内容に対して宛先ショップを記録することと解釈する（ショップごとに出力フォーマットを変える機能はスコープ外）
- 地図表示は Google マップを利用し、住所から位置への解決（ジオコーディング）を含む。利用に必要な API キー等の設定は運用側で用意できることを前提とする
- 地図は「住所の位置確認」が目的であり、ピンの手動調整・経路検索・ストリートビュー等はスコープ外とする
- 同名ショップの重複登録は許容する（系列店・同名店舗がありうるため、重複チェックは行わない）
- 本機能はログイン済みユーザー向けとする
- 申し込みシートへの紐付け（FR-009）は申し込みシート機能（032）のリリースに依存する。032 が未リリースの場合、シートへの紐付けのみ後続で有効化する
