# Feature Specification: アプリの使い方ページ

**Feature Branch**: `worktree-030-usage-guide`

**Created**: 2026-07-08

**Status**: Draft

**Input**: User description: "このアプリの使い方ページを作りたい"

## Clarifications

### Session 2026-07-08

- Q: 使い方ページで説明する機能の範囲は？ → A: 現行 5 セクションに「ログ枠と追加購入」を加えた 6 セクション構成（通知・PDF エクスポート等の周辺機能は初版スコープ外、Living Document として拡充）
- Q: 使い方ページへの導線は共通ナビのどこに置くか？ → A: ヘッダーナビ（モバイルはメニュー内）とフッターの両方に配置
- Q: 初版にスクリーンショット画像を含めるか？ → A: 静的スクリーンショットは使わず、流用可能な箇所はアプリの実 UI 部品（サンプルデータによる例示表示）を流用する。流用が難しい箇所はテキストのみで説明する
- Q: 検索エンジンにインデックスさせるか？ → A: させる（公開ページとして検索結果に表示し、未登録者の流入チャネルとする）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 新規ユーザーが最初のログ作成までの流れを学ぶ (Priority: P1)

登録直後のユーザーが「まず何をすればよいか」を知るために使い方ページを開き、アカウント設定 → ダイブログ作成 → ダッシュボードで振り返り、という基本フローをステップ形式で理解し、案内に沿って最初のダイブログを作成できる。

**Why this priority**: 本アプリの中核価値は「ログを記録して振り返れること」。最初のログ作成に到達できないユーザーは定着しないため、オンボーディングを支える説明が最も価値が高い。

**Independent Test**: 使い方ページを開き、「はじめに」セクションの案内だけを頼りに新規ユーザーがログ作成画面に到達してログを 1 件保存できることで単独検証できる。

**Acceptance Scenarios**:

1. **Given** ログイン済みの新規ユーザーが使い方ページを開いた状態, **When** 「はじめに」セクションを読む, **Then** 基本フロー（プロフィール設定 → ログ作成 → ダッシュボード確認）がステップ順で表示され、各ステップから該当画面への導線がある
2. **Given** 使い方ページの「ダイブログを記録する」セクションを表示中, **When** セクション内の導線を選択する, **Then** ログ作成画面に遷移できる

---

### User Story 2 - 未登録の訪問者がアプリでできることを理解する (Priority: P2)

サービスを知ったばかりの未登録訪問者が、登録前に「このアプリで何ができるのか・どう使うのか」を使い方ページで確認し、利用イメージを持ったうえで登録に進める。

**Why this priority**: 使い方ページは登録判断の材料にもなる。未登録者が閲覧できないと獲得機会を失うが、既存ユーザーの利用継続（P1）ほどの緊急性はない。

**Independent Test**: 未ログイン状態で使い方ページの URL にアクセスし、リダイレクトされずに全セクションを閲覧でき、登録導線から新規登録画面に遷移できることで単独検証できる。

**Acceptance Scenarios**:

1. **Given** 未ログインの訪問者, **When** 使い方ページにアクセスする, **Then** ログイン画面にリダイレクトされず全コンテンツを閲覧できる
2. **Given** 未ログインの訪問者が使い方ページを閲覧中, **When** ページ内の登録導線を選択する, **Then** 新規登録画面に遷移できる
3. **Given** 未ログインの訪問者が使い方ページを閲覧中, **When** ログイン必須機能への導線を選択する, **Then** ログイン画面を経由して該当機能に到達できる（既存の認証フローに従う）

---

### User Story 3 - 既存ユーザーが特定機能の使い方を調べる (Priority: P3)

既存ユーザーが「持ち物リストはどう使うのか」「予定からログを記録するには」など特定機能の使い方を知りたくなったとき、使い方ページの目次から該当セクションに直接移動して答えを得られる。

**Why this priority**: 個別機能のリファレンスとしての価値。基本フロー（P1）と閲覧可否（P2）が成立していれば、目次による探索性は後から拡充できる。

**Independent Test**: 使い方ページの目次から任意のセクション（例: ダイビング予定と持ち物リスト）を選択し、該当セクションの先頭に画面が移動することで単独検証できる。

**Acceptance Scenarios**:

1. **Given** 使い方ページを表示した状態, **When** 目次から特定機能の項目を選択する, **Then** 該当セクションの先頭に移動して内容を読める
2. **Given** 使い方ページの任意のセクションを閲覧中, **When** 「目次に戻る」導線を選択する, **Then** 目次に戻って別のセクションを選び直せる

---

### Edge Cases

- 使い方ページで紹介している機能が未リリース・提供停止になった場合、該当セクションの記載と導線をリリース状態に合わせて更新する（実装が真実・Living Document の運用に従う）
- ログイン必須機能への導線を未ログイン者が選択した場合は、既存の認証ガード（ログイン画面へのリダイレクト）に委ね、使い方ページ側で独自の制御はしない
- 画面幅の狭いモバイル環境でも、目次・本文・UI の例示表示がはみ出さず全コンテンツを閲覧できる
- 拡大表示（200% ズーム）やスクリーンリーダー利用時にも、見出し構造と目次によって目的のセクションへ到達できる

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 使い方ページは未ログインを含むすべての訪問者が閲覧できなければならない（認証によるリダイレクトの対象外とする）
- **FR-002**: ページは次の 6 セクションで構成しなければならない: 「はじめに（登録〜最初のログ作成までの基本フロー）」「ダイブログを記録する」「ダイビング予定と持ち物リスト」「ダッシュボードで振り返る」「みんなのログ・いいね」「ログ枠と追加購入（作成上限とその拡張方法）」
- **FR-003**: ページ先頭に目次を置き、各セクションへページ内移動できなければならない
- **FR-004**: 各セクションには、説明対象の機能画面へ遷移できる導線を少なくとも 1 つ配置しなければならない
- **FR-005**: 未ログイン閲覧者向けに、新規登録画面への導線をページ内に配置しなければならない
- **FR-006**: 使い方ページへの導線をヘッダーナビゲーション（モバイルではメニュー内）とフッターの両方に配置し、全ページから到達できなければならない
- **FR-007**: ページはモバイルファーストで表示され、アクセシビリティ基準（WCAG 2.1 AA・見出し階層・キーボード操作・コントラスト）を満たさなければならない
- **FR-008**: 各セクションの説明は、操作手順をステップ形式（番号付き）で示さなければならない
- **FR-009**: 視覚的な例示は静的スクリーンショットではなく、アプリと同一の UI 表示（サンプルデータによる例示）を流用して示す。流用が難しい箇所はテキストのみで手順が完結するよう記述する
- **FR-010**: 使い方ページは検索エンジンにインデックスされる公開ページとして提供しなければならない（認証必須ページの非公開設定の対象外とする）
- **FR-011**: TOP ダッシュボードの末尾に、使い方ページの導入セクション（見出し「使い方ガイド」・紹介文・使い方ページへの導線）を表示しなければならない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新規ユーザーが使い方ページの案内のみを頼りに、5 分以内に最初のダイブログ作成（保存完了）まで到達できる
- **SC-002**: 使い方ページを開いてから、目的の機能説明セクションに 2 操作以内（目次選択 1 回を含む）で到達できる
- **SC-003**: 未ログイン訪問者が使い方ページから 2 操作以内で新規登録画面に到達できる
- **SC-004**: モバイル・デスクトップのどちらでも、横スクロールなしで全セクションを閲覧できる
- **SC-005**: 使い方ページ公開後、操作方法に関する問い合わせ・つまずき（ログ作成未達で離脱する新規ユーザーの割合）が公開前より減少する

## Assumptions

- 使い方ページは静的な説明コンテンツとし、内容の更新はアプリのリリースと同時に行う（CMS や管理画面からの編集は本機能のスコープ外）
- 説明対象は現行リリース済みの主要機能（認証・ダイブログ・予定/持ち物・ダッシュボード・いいね/タイムライン・ログ枠/追加購入）とし、通知・PDF エクスポート等の周辺機能と管理画面（admin-front）の説明は初版の対象外（Living Document として拡充する）
- 未ログイン閲覧を想定するため認証必須領域の外に置くが、既存の共通レイアウト（ヘッダー・フッター）は流用する
- 視覚補助は実 UI 部品の例示表示（サンプルデータ）を基本とし、静的スクリーンショットは用いない。例示表示は装飾であってもテキストのみで手順が完結するよう記述し、支援技術向けに適切な代替情報を付す
- 動画・チュートリアルツアー（画面上のガイド表示）・多言語対応は本機能のスコープ外
- FAQ・問い合わせフォームは本機能のスコープ外（将来の拡張候補）
