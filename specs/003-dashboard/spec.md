# Feature Specification: ダッシュボード（TOP / 累計統計 / レギュレーターオーバーホール）

**Feature Branch**: `003-dashboard`

**Created**: 2026-06-10

**Status**: Implemented（2026-06-11）

**Input**: 既存仕様書からの移行

## 概要

ログインしたダイバーの「今」を一目で把握できる TOP ページ（ダッシュボード）を提供する。本 feature には以下 3 つの要素を含む。

1. **TOP 画面**（`/`）の構成と認証
2. **累計統計機能**: 自分のダイブから累計本数・潜水時間などを集計
3. **レギュレーターオーバーホール（OH）機能**: 機材登録と OH 期限管理

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ダッシュボードで累計統計と最近のログを確認する (Priority: P1)

ダイバーとして、TOP ページ（`/`）を開くと、自分の統計（総ダイブ数・今年のダイブ・最大水深・ブランク）と直近のダイブログが一目で確認でき、そこから新しいログ記録にすぐ移れる。

> **feat/design-change（2026-07-08）**: TOP の統計表示は FV ヒーローの 4 項目（総ダイブ数 / 今年のダイブ / 最大水深 / ブランク + 最終潜水日）に再構成された。累計潜水時間・訪問スポット数は集計 RPC（`get_dive_stats`）には残るが TOP には表示しない。最新の画面仕様は [screens/top.md](screens/top.md) を参照。

**Why this priority**: 本 feature の中核価値。「ダイバーとしての歩みを実感できる」体験と、日常的な利用の入口（新規記録・一覧への導線）を提供する。レギュレーター機能がなくても、このストーリーだけで TOP ページとして成立する MVP になる。

**Independent Test**: ダイブログを複数件登録したユーザーでログインして `/` を開き、FV 統計 4 項目と直近 3 件のログ、「ログを作成」CTA が表示されることを確認できる。レギュレーター機能とは独立にテスト可能。

**Acceptance Scenarios**:

1. **Given** 未認証のユーザー, **When** `/` を開く, **Then** `/login` にリダイレクトされる
2. **Given** 認証済みでダイブログが複数件あるユーザー, **When** `/` を開く, **Then** FV ヒーロー（ユーザー名 + FV 統計 4 項目（総ダイブ数 / 今年のダイブ / 最大水深 / ブランク）+ 「ログを作成」CTA）、最近のダイブログ（直近 3 件・代表写真付き）が表示される
3. **Given** 認証済みでダイブログが 0 件のユーザー, **When** `/` を開く, **Then** 各統計が `0`（ブランクは「—」）で表示され、最近のログ欄に「最初のログを記録しよう」CTA が表示される
4. ~~**Given** 累計潜水時間が 60 分以上のユーザー, **When** 統計カードを見る, **Then** 「XX 時間 YY 分」形式で表示される~~（feat/design-change で累計潜水時間は TOP 非表示。RPC の集計仕様は FR-003 のまま）
5. ~~**Given** 累計潜水時間が 60 分未満のユーザー, **When** 統計カードを見る, **Then** 「YY 分」形式で表示される~~（同上）

### User Story 2 - レギュレーターを登録して管理する (Priority: P2)

ダイバーとして、`/settings/equipment` でレギュレーター（メイン / バックアップなど複数）を登録・編集・削除し、OH 期限管理の元になる機材情報を管理できる。

**Why this priority**: OH ステータス表示（US3）・OH 完了記録（US4）の前提となるデータ入力機能。ダッシュボード本体（US1）の次に必要。

**Independent Test**: 認証済みユーザーで `/settings/equipment` を開き、レギュレーターの新規登録 → 一覧表示 → 編集 → 削除の一連の操作ができることを、TOP の表示とは独立に確認できる。

**Acceptance Scenarios**:

1. **Given** 認証済みユーザー, **When** `/settings/equipment` を開く, **Then** 登録済みのレギュレーター一覧が表示される
2. **Given** レギュレーター新規登録フォーム, **When** 必須項目（ブランド / モデル / 前回 OH 日）を入力して送信する, **Then** レギュレーターが保存される
3. **Given** レギュレーターを 1 件も登録していないユーザー, **When** 最初の 1 件を登録する, **Then** 自動的に `is_primary = true` になる
4. **Given** 登録済みのレギュレーター, **When** 編集・削除を行う, **Then** 変更が反映される
5. **Given** 同一ユーザー, **When** 複数のレギュレーターを登録する, **Then** `is_primary = true` は常に 1 件のみである

---

### User Story 3 - TOP でレギュレーターの OH 期限を把握する (Priority: P3)

ダイバーとして、TOP ページでメイン機材（`is_primary = true`）のオーバーホール期限（次回推奨日・残日数・残本数・ステータス）を確認し、安全のためのメンテナンス時期を忘れずに把握できる。

**Why this priority**: 安全面のリマインダーとして重要だが、US1（ダッシュボード）と US2（機材登録）が揃って初めて意味を持つため P3。

**Independent Test**: レギュレーター登録済みユーザーで TOP を開き、`last_overhauled_on` と周期設定・ダイブ本数の組み合わせを変えて「余裕 / 期限間近 / 期限切れ」の各表示を確認できる。

**Acceptance Scenarios**:

1. **Given** メイン機材を登録済みの認証済みユーザー, **When** TOP を開く, **Then** メイン機材の OH ステータスが表示される
2. **Given** レギュレーター未登録のユーザー, **When** TOP を開く, **Then** 「レギュレーターを登録すると OH 期限をお知らせします」と登録画面へのリンクが表示される
3. **Given** 残日数 > 30 日 かつ 残本数 > 10 本, **When** TOP を開く, **Then** ステータス「余裕」（青系）が表示される
4. **Given** 残日数 ≤ 30 日 または 残本数 ≤ 10 本, **When** TOP を開く, **Then** ステータス「期限間近」（黄系）が表示される
5. **Given** 残日数 ≤ 0 または 残本数 ≤ 0, **When** TOP を開く, **Then** ステータス「期限切れ」（赤系）が表示される
6. **Given** いずれのステータス, **When** 表示を確認する, **Then** 色 + アイコン + テキストで識別できる（色だけに依存しない）

---

### User Story 4 - OH 完了をワンタップで記録する (Priority: P4)

ダイバーとして、オーバーホールを実施したら TOP の OH カードから 1 タップで「完了」を記録し、期限カウントをリセットできる。

**Why this priority**: 運用上の利便性向上。US3 の表示機能の上に成立する追加操作のため最後。

**Independent Test**: メイン機材登録済みユーザーで TOP の「メンテ完了を記録」ボタンを押し、確認 → 記録 → ステータス再計算の流れを確認できる。

**Acceptance Scenarios**:

1. **Given** TOP の OH カード, **When** 表示を確認する, **Then** 「メンテ完了を記録」ボタンが表示されている
2. **Given** 「メンテ完了を記録」ボタン, **When** クリックする, **Then** 確認ダイアログが表示される
3. **Given** 確認ダイアログ, **When** OK を押す, **Then** `last_overhauled_on = 今日` に更新される
4. **Given** OH 完了記録後, **When** TOP を見る, **Then** OH ステータスが新しい計算結果に切り替わっている

---

### Edge Cases

- ダイブログが 0 件のとき: 各統計を `0` で表示し、TOP はエラーなく描画される（「最初のログを記録しよう」CTA を表示）
- レギュレーター未登録のとき: OH パネルは設定誘導 CTA に置き換わり、TOP はエラーなく描画される
- 残日数・残本数の境界値: 残日数 0 / 30 / 31、残本数 0 / 10 / 11 でステータスが正しく切り替わる（0 以下 = 期限切れ、30 以下 / 10 以下 = 期限間近、それ以外 = 余裕）
- 集計クエリが失敗したとき: 統計カードに「集計に失敗しました」を表示し、各値は `-`
- レギュレーター取得が失敗したとき: OH パネルにエラー文言と設定画面への導線を表示
- 他ユーザーのレギュレーター ID を URL 指定したとき: RLS により 0 件返却となり `notFound()`（404）
- OH 完了記録の Server Action が失敗したとき: トースト通知（`role="alert"`）でエラーを伝える
- OH 完了を誤って記録したとき: 取り消し機能は対象外。edit 画面で `last_overhauled_on` を手動修正する

## Requirements *(mandatory)*

### Functional Requirements

#### TOP ページ（`/`）

- **FR-001**: システムは、未認証ユーザーが `/` を開いたとき `/login` にリダイレクトしなければならない
- **FR-002**: システムは、認証済みユーザーが `/` を開いたとき、以下のセクションを含むダッシュボードを表示しなければならない: FV ヒーロー（ユーザー名 + FV 統計 4 項目 + 次の予定 + 「ログを作成」CTA）/ 次のダイビング予定（最大 3 件・004）/ 最近のダイブログ（直近 3 件・代表写真付き）/ タイムライン・いいねタブ（021 / 027）/ レギュレーター OH 状況パネル / 統計の推移（010）

#### 累計統計

- **FR-003**: システムは、認証済みユーザー自身のダイブから以下を集計して表示しなければならない: 累計ダイブ本数（行数）/ 累計潜水時間（`bottom_time_min` の合計）/ 最大水深（`max_depth_m` の最大値）/ 訪問スポット数（サイト参照（`dive_site_id`）または自由入力（`location`）の distinct カウント）
- **FR-004**: システムは、ダイブログが 0 件のとき各統計を `0` で表示し、最近のログ欄に「最初のログを記録しよう」CTA を表示しなければならない
- **FR-005**: システムは、累計潜水時間を「XX 時間 YY 分」形式で表示しなければならない（60 分未満なら「YY 分」）
  - **注（feat/design-change）**: 累計潜水時間・訪問スポット数は TOP に表示しなくなった（RPC の集計は維持）。TOP の表示項目は FV 統計 4 項目（総ダイブ数 / 今年のダイブ / 最大水深 / ブランク + 最終潜水日）。詳細は [screens/top.md](screens/top.md)

#### 機材登録（`/settings/equipment`）

- **FR-006**: システムは、認証済みユーザーが `/settings/equipment` を開いたとき、登録済みのレギュレーター一覧を表示しなければならない
- **FR-007**: ユーザーは複数のレギュレーター（メイン / バックアップなど）を登録できなければならない
- **FR-008**: システムは、必須項目（ブランド / モデル / 前回 OH 日）が入力・送信されたときレギュレーターを保存しなければならない
- **FR-009**: ユーザーは登録済みのレギュレーターを編集・削除できなければならない
- **FR-010**: システムは、同一ユーザーで `is_primary = true` のレギュレーターを 1 件のみに制約しなければならない
- **FR-011**: システムは、最初に登録されたレギュレーターを自動的に `is_primary = true` にしなければならない

#### OH ステータス表示（TOP 上）

- **FR-012**: システムは、認証済みユーザーが TOP を開いたとき、メイン機材（`is_primary = true`）の OH ステータスを表示しなければならない
- **FR-013**: システムは、レギュレーター未登録のとき「レギュレーターを登録すると OH 期限をお知らせします」と表示し、登録画面へのリンクを提供しなければならない
- **FR-014**: システムは、OH ステータスを以下のルールで判定しなければならない:
  - **余裕あり**: 残日数 > 30 日 かつ 残本数 > 10 本
  - **期限間近**: 残日数 ≤ 30 日 または 残本数 ≤ 10 本
  - **期限切れ**: 残日数 ≤ 0 または 残本数 ≤ 0
  - 残日数 = `next_overhaul_date - 今日`
  - 残本数 = `overhaul_interval_dives - (last_overhauled_on 以降のダイブ本数)`
- **FR-015**: システムは、ステータスを色（青 / 黄 / 赤）+ アイコン + テキストで識別可能にしなければならない（色だけに依存しない）

#### OH 完了の記録

- **FR-016**: システムは、TOP の OH カードに「メンテ完了を記録」ボタンを表示しなければならない
- **FR-017**: システムは、ボタンクリック時に確認ダイアログを表示し、OK が押されたとき `last_overhauled_on = 今日` に更新しなければならない
- **FR-018**: システムは、更新後に TOP の OH ステータスを新しい計算結果に切り替えなければならない

#### データアクセス

- **FR-019**: システムは、統計・機材データを認証ユーザー本人のものに限定しなければならない（RLS で保証）

### Key Entities

- **regulators（新規）**: ユーザーが登録するレギュレーター機材。ブランド / モデル / 前回 OH 日（必須）、購入日 / OH 推奨周期（月・本数）/ メイン機材フラグ / メモを持つ。ユーザーに従属し（user 1 : N regulators）、メイン機材は 1 ユーザー 1 件。詳細なカラム定義は [plan.md のデータモデル節](./plan.md#データモデル)を参照
- **dives（既存・参照のみ）**: 累計統計（本数 / 潜水時間 / 最大水深 / 訪問スポット数）と「OH 以降のダイブ本数」の集計元。本 feature ではスキーマ変更なし（[specs/002-dive-log-crud/data-model.md](../002-dive-log-crud/data-model.md)）
- **users（既存・参照のみ）**: `regulators.user_id` の FK 参照先。ヒーローのユーザー名表示にも使用（[specs/001-auth/data-model.md](../001-auth/data-model.md)）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 認証済みユーザーが TOP を 1 画面開くだけで、FV 統計 4 項目・メイン機材の OH ステータス・直近 3 件のログをすべて確認できる
- **SC-002**: 未認証で `/` にアクセスすると 100% `/login` に遷移する
- **SC-003**: ダイブログ 0 件・レギュレーター未登録のいずれの状態でも、TOP がエラーなく描画される
- **SC-004**: 「メンテ完了を記録」操作後、TOP の OH ステータスが即座に（同一画面内の再描画で）新しい計算結果に更新される
- **SC-005**: 他ユーザーのレギュレーター・ダイブデータは一切読み書きできない（RLS で遮断、URL 直叩きは 404）
- **SC-006**: 全カラーコントラスト比が WCAG AA（4.5:1 以上）を満たす（特に警告 / エラー色）

## Assumptions

- 001 認証 / 002 ダイブログ CRUD の feature が完了していることを前提とする
- レギュレーターのデータモデルは複数機材対応の別テーブル方式（`regulators` テーブル新規作成）を採用する（旧 screens/top.md の TBD「案 A / 案 B」は案 B で確定済み）
- OH 警告の閾値は「残日数 30 日 / 残本数 10 本」で確定とする
- OH 完了記録アクションは TOP の OH カード上に配置する
- 累計統計は都度集計（DB 側集計）で十分なデータ量を想定する（キャッシュ層は導入しない）
- 既存の `handle_updated_at()` トリガ関数・`dives(user_id, dive_date)` インデックスを再利用できる
- `@repo/supabase` パッケージと Supabase ローカル環境が利用可能

## Out of Scope（Phase 1 対象外）

- 月別ダイブ本数グラフ（後続の feature で検討）
- レギュレーター以外の機材（BCD / ダイブコンピューターなど）の管理
- メイン機材切替 UI（最初の 1 件を自動で primary に。切替は edit 画面の `is_primary` チェックで対応）
- OH 完了の取り消し（操作ミス時は edit 画面で手動修正）
- カレンダー方式以外の OH リマインダー（メール通知など）

- `src/app/page.tsx` を Welcome から本 feature のダッシュボードに置き換える
