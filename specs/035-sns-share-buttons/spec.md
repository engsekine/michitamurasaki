# Feature Specification: SNS 共有ボタン

**Feature Branch**: `035-sns-share-buttons`

**Created**: 2026-07-16

**Status**: Draft

**Input**: User description: "SNS共有ボタンの追加。ダイビングログ（公開ログの共有ページ）とユーザープロフィール（公開プロフィール）を Instagram / X / Facebook で共有できるようにする。各 SNS のブランドアイコン（SVG）を用意して共有ボタンとして表示する。"

## Clarifications

- Session 2026-07-16: **Instagram 共有は削除**。Instagram は Web の共有インテント（URL 指定共有）を提供しておらず、代替の「リンクコピー + Instagram を開く」方式も投稿まで完結しない UX のため提供しない。対象 SNS は X / Facebook の 2 つとする（FR-005 / FR-010 を削除、関連シナリオ・エッジケースを改定）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 公開ダイビングログを SNS で共有する (Priority: P1)

ユーザーは公開設定にしたダイビングログの詳細ページ（`/dives/[id]`）で、X・Facebook のブランドアイコン付き共有ボタンを使い、ログの共有リンクを各 SNS に投稿できる。どちらもワンクリックで投稿画面（共有ダイアログ）が開く。

**Why this priority**: ログの共有はこの機能の主目的。現在はリンクの手動コピーしかなく、SNS へ投稿するまでの手数が多い。ダイビングの成果を仲間に見せたいというモチベーションに直結する。

**Independent Test**: 公開ログの詳細ページで 2 つの共有ボタンが表示され、X / Facebook で共有リンク入りの投稿画面が開くことを確認できれば単体でテスト可能。

**Acceptance Scenarios**:

1. **Given** 公開設定のログの詳細ページ, **When** ページを表示する, **Then** X・Facebook のブランドアイコン付き共有ボタンが表示される
2. **Given** 公開ログの詳細ページ, **When** X の共有ボタンを押す, **Then** 共有テキスト（場所・日付など）と共有リンク（`/dives/[id]`）が入った X の投稿画面が新しいタブで開く
3. **Given** 公開ログの詳細ページ, **When** Facebook の共有ボタンを押す, **Then** 共有リンクが入った Facebook の共有ダイアログが新しいタブで開く
4. **Given** 非公開設定のログの詳細ページ, **When** ページを表示する, **Then** SNS 共有ボタンは表示されない（リンク先が本人以外閲覧できないため）
5. **Given** 他人の公開ログの詳細ページ, **When** ページを表示する, **Then** 閲覧者にも同じ SNS 共有ボタンが表示され共有できる

---

### User Story 2 - ユーザープロフィールを SNS で共有する (Priority: P2)

ユーザーはプロフィールページ（`/users/<ユーザー ID>`）で同じ 2 つの共有ボタンを使い、プロフィールの URL を各 SNS に投稿できる。自分のプロフィールを共有してフォロワーを増やす用途と、他人のプロフィールを仲間に紹介する用途の両方に使える。

**Why this priority**: ログ共有に次ぐ導線。ユーザー ID 方式の URL（034）は「常にそのまま読める・共有しやすい」ことが目的であり、その価値を SNS 共有ボタンで完結させる。

**Independent Test**: プロフィールページ（自分・他人とも）で 2 つの共有ボタンが表示され、各 SNS の共有動作（US1 と同じ挙動）がプロフィール URL に対して行われることを確認できれば単体でテスト可能。

**Acceptance Scenarios**:

1. **Given** 自分のプロフィールページ, **When** ページを表示する, **Then** X・Facebook の共有ボタンが表示される
2. **Given** プロフィールページ, **When** X の共有ボタンを押す, **Then** 共有テキスト（ニックネームなど）とプロフィール URL（`/users/<ユーザー ID>`）が入った X の投稿画面が新しいタブで開く
3. **Given** 他人のプロフィールページ, **When** ページを表示する, **Then** 同じ共有ボタンが表示され、その人のプロフィール URL が共有対象になる

---

### Edge Cases

- ブラウザのポップアップブロックで新しいタブが開けない場合でも、ボタンはリンクとして機能する（`target="_blank"` のリンク遷移であればブロックされない）
- ログの場所名やニックネームに `#` `&` などの記号・絵文字が含まれる場合も、共有テキスト・URL が正しくエンコードされて欠落しない
- 共有リンク先（`/dives/[id]`・`/users/<ユーザー ID>`）の閲覧にはログインが必要（既存仕様のまま）。共有を受け取った未ログインユーザーはログイン後に閲覧できる
- 共有後にログが非公開化・ユーザー ID が変更された場合、共有済みリンクは既存仕様どおり無効（閲覧不可・404）になる。本機能はこの挙動を変えない

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは公開設定のダイビングログ詳細ページに、X・Facebook の 2 つの SNS 共有ボタンを表示しなければならない。非公開ログでは表示してはならない
- **FR-002**: システムはプロフィールページ（自分・他人とも）に同じ 2 つの SNS 共有ボタンを表示しなければならない
- **FR-003**: X の共有ボタンは、共有テキストと共有 URL を含んだ X の投稿画面を新しいタブで開かなければならない
- **FR-004**: Facebook の共有ボタンは、共有 URL を含んだ Facebook の共有ダイアログを新しいタブで開かなければならない
- **FR-005**: 削除（2026-07-16 改定）。Instagram 共有は提供しない（Clarifications 参照）
- **FR-006**: 共有テキストは、ログ共有では場所と日付を、プロフィール共有ではニックネームを含む定型文とする
- **FR-007**: 共有 URL は既存の共有リンク（ログ: `{SITE_URL}/dives/[id]`、プロフィール: `{SITE_URL}/users/<ユーザー ID>`）をそのまま使用し、閲覧権限・アクセス制御は一切変更してはならない
- **FR-008**: 各共有ボタンは各 SNS のブランドアイコン（SVG）を表示する。アイコンは外部サービスに依存せずアプリ内に同梱し、各社のブランドガイドラインに沿った形状・配色とする
- **FR-009**: 各共有ボタンは SNS 名を含むアクセシブルな名前（例: 「X で共有」）を持ち、キーボードのみで操作でき、WCAG 2.1 AA を満たさなければならない
- **FR-010**: 削除（2026-07-16 改定）。クリップボードコピーのフォールバックは Instagram 共有の削除に伴い不要（Clarifications 参照）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは公開ログ詳細・プロフィールの表示から 1 クリックで各 SNS の共有画面に到達できる
- **SC-002**: X / Facebook の共有画面に共有リンクと共有テキストが欠落・文字化けなく引き渡される（記号・絵文字を含むケースで 100%）
- **SC-003**: 非公開ログに SNS 共有ボタンが表示される事故が 0 件
- **SC-004**: 共有ボタン一式がキーボードのみで操作でき、アクセシビリティ自動チェック（WCAG 2.1 AA）で違反 0 件

## Assumptions

- 対象 SNS は X / Facebook の 2 つ（2026-07-16 改定）。Instagram は Web からの URL 指定共有（共有インテント）を提供しておらず提供しない。モバイルネイティブの共有シート（Web Share API）連携は本機能のスコープ外とし、将来拡張とする
- 共有リンク先の閲覧にはログインが必要という既存仕様（021 / 034）は変更しない。したがって SNS 上でのリンクプレビュー（OGP 画像等）の充実は本機能のスコープ外とする（未ログインのクローラーはページ内容を取得できない）
- LINE 等の他 SNS、共有回数の計測・分析はスコープ外
- 新しいデータの保存は発生しない（DB 変更なし）
- ブランドアイコンは各社が公開しているロゴを元にした SVG をアプリ内に静的に持つ（外部 CDN・アイコンフォントは使わない）
