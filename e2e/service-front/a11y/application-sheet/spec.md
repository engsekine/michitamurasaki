# application-sheet（E2E 仕様）

## 目的

申し込みシート（/application-sheet）は入力項目が多く、レンタル器材の有無で表示ブロックが動的に切り替わるため、状態ごとに WCAG 2.1 AA 違反が入り込みやすい。フォームの各表示状態で axe 違反がないことと、マウスなしでも入力・コピーまで完了できることを守る。

## 対象

- アプリ: service-front（http://localhost:9323）
- 画面 / URL: `/application-sheet`
- 関連仕様: `specs/032-dive-application-form/spec.md`（FR-006 コピーと完了フィードバック、FR-008 自動入力値の上書き、FR-011 / FR-012 レンタル「無」時の入力欄非表示と省略トグル）

## 前提

- 認証: ログイン済み（setup project の storageState）
- Cookie 同意: 同意済みプリセット（fixture 既定）
- データ: seed のみ（お名前はプロフィールから自動入力される前提）
- その他: `test.use({ permissions: ['clipboard-write'] })` — コピー機能（`navigator.clipboard.writeText`）の検証に必要

## シナリオ

| # | テスト名 | 検証内容 |
|---|---|---|
| 1 | /application-sheet - WCAG 2.1 AA 違反なし（要認証） | h1「申し込みシート」表示後に axe を実行。続けてレンタル「有」で品目 14 種のチェックボックスを展開した状態、レンタル「無」で「未該当ブロックを省略する」トグルを表示した状態でもそれぞれ違反がないことを確認する。 |
| 2 | /application-sheet - キーボード操作で入力とコピーができる（要認証） | 「お名前」を空にしてキーボード入力し生成テキストへ反映されること、ドライスーツ経験のラジオを focus + Space で選択できること、「コピーする」を focus + Enter で実行すると `role="status"` の「コピーしました」が表示されることを確認する。 |

## 備考

- シナリオ 2 では `waitForHydration` でハイドレーション完了を待ってからフォームをクリアする。自動入力（プロフィール / 保存済み基本情報）はハイドレーション後に反映されるため、その前に空にすると復元されて入力が後ろに追記される。
- 「お名前」の空クリア → 再入力は、FR-008（自動入力値の上書き）の検証も兼ねている。
