# plans-pages（E2E 仕様）

## 目的

ダイビング予定（`/plans` 系）の一覧・作成フォーム・詳細（持ち物リスト）の 3 画面が WCAG 2.1 AA 違反なく表示されることを守る。詳細画面は seed に依存せず、テスト内で予定を 1 件作成して検証し、後始末で削除する。

## 対象

- アプリ: service-front（http://localhost:9323）
- 画面 / URL:
  - `/plans`（予定一覧）
  - `/plans/new`（予定作成フォーム）
  - `/plans/[id]`（作成した予定の詳細。持ち物リストを含む）
- 関連仕様: `specs/004-top-dive-plans/spec.md`（FR-001 一覧、FR-002 作成、FR-004 削除確認ダイアログ、FR-010〜 持ち物リスト）

## 前提

- 認証: ログイン済み（setup project の storageState）
- Cookie 同意: 同意済みプリセット（fixture 既定）
- データ: テスト内で予定 1 件（予定日 `2026-12-01`・ポイント名「a11y テスト用ポイント」）を作成し、テスト末尾で削除する（持ち物は cascade で消える）
- その他: 作成フォームの入力前に `waitForHydration` でクライアント側ハイドレーション完了を待つ

## シナリオ

| # | テスト名 | 検証内容 |
|---|---|---|
| 1 | /plans 系 3 画面 - WCAG 2.1 AA 違反なし（要認証） | `/plans` をスキャン → `/plans/new` をハイドレーション待ち後にスキャン → 予定日・ポイント名を入力して「作成する」を押し、`/plans/[uuid]` への遷移後にスキャン。最後に「削除」ボタン → dialog 内の「削除」で予定を削除し、`/plans` に戻ることを待つ。各画面で `expectNoViolations` により違反が無いことを検証する。 |

## 備考

- `/plans/new` は react-hook-form のフォームのため、ハイドレーション前に `fill` すると入力が消える／追記される（CI の低速 dev サーバーで再現）。`waitForHydration` を挟んでから入力する。
- 後始末の削除は確認ダイアログを経由する（dialog 内の「削除」ボタンをクリック）。
