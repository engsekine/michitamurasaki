# dives-pages（E2E 仕様）

## 目的

ダイブログの一覧・詳細はアプリの中核画面で、潮回りラベル・SNS 共有ボタン・検索フィルタの詳細条件パネルなど機能追加ごとに UI 要素が増えている。これらの表示状態それぞれで WCAG 2.1 AA 違反がないことを守る。

## 対象

- アプリ: service-front（http://localhost:9323）
- 画面 / URL: `/dives`（一覧・検索フィルタ）、`/dives/new`（ログ作成の経路）、`/dives/:id`（詳細）
- 関連仕様: `specs/007-tide-phase-display/spec.md`（潮回りラベル）、`specs/035-sns-share-buttons/spec.md`（公開ログの SNS 共有ボタン）、`specs/013-dive-search-filters/spec.md`（FR-012 詳細条件パネル）

## 前提

- 認証: ログイン済み（setup project の storageState）
- Cookie 同意: 同意済みプリセット（fixture 既定）
- データ: seed に加え、シナリオ 1 でログ（2026-04-15 / ポイント名「a11y テスト用ポイント」/ 18m / 40 分）を 1 件作成し、末尾で削除する
- その他: なし

## シナリオ

| # | テスト名 | 検証内容 |
|---|---|---|
| 1 | /dives 系 2 画面 - WCAG 2.1 AA 違反なし（要認証） | `/dives` 一覧で axe を実行。`/dives/new` からログを 1 件作成し詳細で axe を実行。さらに「このログを公開する」スイッチを ON にして「X で共有」リンクが表示された状態でも違反がないことを確認し、後始末として削除ダイアログからログを削除する。 |
| 2 | /dives 検索フィルタ詳細条件パネル展開時 - WCAG 2.1 AA 違反なし（要認証） | `/dives` で「詳細条件を開く」ボタンを押し、「開始日」「ダイブタイプ」の入力が表示された状態で axe を実行し違反がないことを確認する。 |

## 備考

- ログ作成フォームの入力前に `waitForHydration` でハイドレーション完了を待つ（SSR 直後に fill すると入力が消える対策）。
- シナリオ 1 が途中で失敗すると作成したログが残る（後始末はテスト末尾で行うのみ）。
