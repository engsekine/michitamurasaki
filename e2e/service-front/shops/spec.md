# shops（E2E 仕様）

## 目的

ショップ管理（033-dive-shops）の CRUD・バリデーション・認証ガードが画面を通して機能することを守る。さらに、ショップを予定・ログ・申し込みシートに紐付けたときの逆引き表示、公開ログを他ユーザーが見てもショップ情報が漏れないこと、ショップ削除で紐付け先データが消えないことを一連のシナリオで確認する。a11y（axe）は別の a11y spec が担保するため、ここでは扱わない。

## 対象

- アプリ: service-front（http://localhost:9323）
- 画面 / URL: `/shops`、`/shops/new`、`/shops/[id]`、`/shops/[id]/edit`、`/`（ヘッダーナビ）、`/plans/new`、`/plans/[id]`、`/dives/new`、`/dives/[id]`、`/application-sheet`、`/application-sheet?sheet=…`、`/login`（未認証時のリダイレクト先）
- 関連仕様: `specs/033-dive-shops/spec.md`（US1〜US3、FR-009 / FR-010 / FR-015 / FR-016、SC-005）、`specs/033-dive-shops/quickstart.md`（シナリオ 1〜5）

## 前提

- 認証: ログイン済み（setup project の storageState）。ただし「未認証」describe は `test.use({ storageState: NO_AUTH })` で未認証。紐付けシナリオでは `browser.newContext({ storageState: NO_AUTH })` で別コンテキストを作り、`loginWithPassword` で `SERVICE_BUDDY_USER`（buddy@example.com）にテスト内でログインして公開ビューを閲覧する
- Cookie 同意: 同意済みプリセット（fixture 既定）。別コンテキスト（buddy）には `presetConsent` を直接呼んでプリセットする
- データ: seed のテストユーザー（test@example.com / buddy@example.com）。ショップ・予定・ログ・申し込みシートはテスト内で作成し、テスト末尾で削除する。名前・ダイブ番号は `Date.now()` ベースで実行ごとに一意化する（ダイブ番号は 9000 + 3 桁）
- その他: 紐付けシナリオは `test.slow()` で標準の 3 倍のタイムアウト。地図プレビューの表示待ちは 15 秒、シート保存完了の待ちは 15 秒に延長

## シナリオ

| # | テスト名 | 検証内容 |
|---|---|---|
| 1 | 未認証で /shops にアクセスするとログイン画面へリダイレクトされる | 未認証で `/shops` を開き、URL が `/login` に変わることを assert する（US2・proxy の契約） |
| 2 | ショップの登録・一覧・詳細・編集・削除が一連で行える | `/shops` の h1「ショップ」→「ショップを登録」→ 名前・電話・URL・メモを入力して登録し、詳細に h1・`tel:` リンク・`target=_blank` の Web リンクが出ることを確認。一覧表示 → 編集で名前を更新 → 削除で一覧から消えることを assert する |
| 3 | ショップ名が空のまま登録するとエラーが表示され登録されない | `/shops/new` で未入力のまま「登録する」を押し、「ショップ名を入力してください」が表示され URL が `/shops/new` のままであることを assert する |
| 4 | 不正な URL 形式ではエラーが表示され登録されない | Web サイト URL に `htp://example` を入力して登録し、「Web サイト URL は http(s):// から始まる URL を入力してください」が表示され `/shops/new` に留まることを assert する |
| 5 | ヘッダーナビに「ショップ」導線が表示される | `/` を開き、リンク「ショップ」の `href` が `/shops` であることを assert する |
| 6 | 住所を入力して確定すると、地図プレビューまたは「表示できない」メッセージが自動で出る | `/shops/new` で住所を入力しフォーカスを外すと、title「入力中の住所 の地図」のプレビューか status「住所から地図を表示できません」のいずれかが表示される。住所を空に戻して確定すると両方が消えることを assert する（US3） |
| 7 | 予定・ログ・シートへの紐付けと、ショップ削除時の解除・公開ビュー非表示が機能する | ショップ登録後、予定・ログの作成フォームでショップを選択し、各詳細にショップ名リンク（`href` = ショップ詳細）が出ることを確認。申し込みシートに宛先ショップを保存し、再度開くと選択が復元される（FR-009）。ショップ詳細の逆引き一覧に予定・ログのリンクが出る（FR-016）。ログを公開して buddy ユーザーで閲覧すると見出しは見えるがショップ名は出ない（FR-015）。ショップを削除しても予定・ログは残りショップ名だけ消える（FR-010 / SC-005）。最後に予定・ログ・シートを削除して後始末する |

## 備考

- 失敗時の残骸と衝突しないよう、ショップ名・シート名・ダイブ番号は実行ごとに一意な値を採る（`selectOption` の label 一致を一意にする目的も兼ねる）
- `GOOGLE_MAPS_API_KEY` はサーバー側 env でテストプロセスから参照できないため、地図プレビューは「表示される」か「表示できないメッセージが出る」のどちらかを許容する
- 予定・ログの作成フォームは `waitForHydration` でハイドレーション完了を待ってから入力する（SSR 直後の fill は React の初期値上書きで消えるため）
- 申し込みシートは、お名前の入力が「生成テキスト」プレビューに反映されること（= React が動作していること）を確認してから `selectOption` する（ハイドレーション前の選択は react-hook-form に拾われない）
- 申し込みシートの削除は `window.confirm` を使うため `page.on('dialog')` で承諾する
- 紐付けシナリオは並列実行中の dev サーバーのオンデマンドコンパイルで各遷移が延びるため `test.slow()` を付ける
