# application-sheet-flows（E2E 仕様）

## 目的

申し込みシートは「入力 → 名前を付けて保存 → 後日一覧から復元」という往復が価値の中心で、スナップショットにレンタル選択などが欠けると復元時に入力し直しになる。保存・復元・削除・基本情報の自動入力・TOP からの導線・認証境界を、実際のブラウザ操作で通しで守る。

## 対象

- アプリ: service-front（http://localhost:9323）
- 画面 / URL: `/application-sheet`、`/application-sheet?sheet=<id>`、`/`（TOP の導線）、`/login`（未認証リダイレクト先）
- 関連仕様: `specs/032-dive-application-form/spec.md`（FR-001 TOP からの導線、FR-010 名前付き保存・一覧・復元・削除、FR-014 基本情報の保存）

## 前提

- 認証: ログイン済み（setup project の storageState）。`未認証` describe のみ `test.use({ storageState: NO_AUTH })` で未認証
- Cookie 同意: 同意済みプリセット（fixture 既定）
- データ: テスト内で作成する。シート名は `E2E テスト <Date.now()>`、携帯電話は `090` + タイムスタンプ末尾 8 桁で実行ごとに一意にする。シートはテスト内で削除して後始末するが、基本情報（携帯電話・最寄りの駅・ライセンスランク）は保存したまま残る
- その他: 削除確認の `confirm` ダイアログは `page.on('dialog')` で常に承認する

## シナリオ

| # | テスト名 | 検証内容 |
|---|---|---|
| 1 | 申し込みシート: 名前を付けて保存 → 一覧から選択で全項目復元 → 削除（FR-010） | 携帯電話・最寄りの駅・レンタル器材「有」・フィンを入力しシート名を付けて「シートを保存する」→ status に「保存しました」が出てボタンが「上書き保存する」に変わる。再訪問して一覧のリンクから開くと `?sheet=` 付き URL に遷移し全項目（レンタル選択含む）が復元される。「<シート名>を削除」で `?sheet=` なしの新規状態に戻り、一覧から消える。 |
| 2 | 申し込みシート: 基本情報と経験を保存すると新規シート作成時に自動入力される | 携帯電話・最寄りの駅・ライセンスランクを入力して「基本情報を保存する」→ status に「基本情報を保存しました」。再訪問した新規シート作成状態で 3 項目が自動入力されていることを assert する。 |
| 3 | 申し込みシート: TOP ダッシュボードの導線から遷移できる（FR-001） | `/` の「申し込みシートを作る」リンクをクリックし、`/application-sheet` に遷移して h1「申し込みシート」が表示されることを assert する。 |
| 4 | 申し込みシート: 未認証アクセスは /login へリダイレクトされる | 未認証で `/application-sheet` を開くと `/login` に遷移し、「メールアドレス」入力欄が表示されることを assert する。 |

## 備考

- 繰り返し実行しても前回分と衝突しないよう、シート名・携帯電話にタイムスタンプを含めて一意化している
- 復元確認の前に `/` → `/application-sheet` と遷移し直すのは、同一ページ内の状態ではなく再訪問で一覧・自動入力が効くことを見るため
- 一覧のリンクは `RegExp(sheetName)` で名前一致させる（更新日時などが同じリンク内に含まれるため部分一致）
